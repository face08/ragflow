# 核心函数流程图

## 概述

本文档描述RAGFlow项目中6个核心chunk处理函数的详细流程。这些函数是所有chunk规则的基础，被naive、paper、book等多个规则模板调用。

核心函数列表：
1. **naive_merge**: Token预算驱动的朴素合并策略
2. **hierarchical_merge**: 层级化合并策略（保留文档结构）
3. **tokenize_chunks**: 将文本块转换为最终chunk文档格式
4. **tokenize_table**: 表格专用tokenization
5. **naive_merge_docx**: DOCX文档专用朴素合并
6. **add_positions**: 为chunk添加页码和位置元数据

## 函数1: naive_merge - 朴素合并策略

### 功能说明
基于token预算和分隔符的简单合并策略，将多个文本段落合并为固定token数的chunk。支持重叠策略（overlap）以保持上下文连续性。

### 流程图

```mermaid
graph TD
    Start[开始: naive_merge] --> Input[输入参数:<br/>- sections文本段落列表<br/>- chunk_token_num目标token数<br/>- delimiter分隔符<br/>- overlapped_percent重叠比例]
    
    Input --> InitVars[初始化变量:<br/>- chunks结果列表<br/>- current_chunk当前累积段落<br/>- token_count当前token计数]
    
    InitVars --> LoopSections[遍历sections]
    
    LoopSections --> GetSection[获取当前段落<br/>text, layout_type]
    
    GetSection --> CountTokens[计算段落token数<br/>使用rag_tokenizer]
    
    CountTokens --> CheckBudget{current_token<br/>+ section_token<br/><= chunk_token_num?}
    
    CheckBudget -->|是| AddToChunk[添加到current_chunk<br/>累加token_count]
    CheckBudget -->|否| FlushChunk[输出current_chunk]
    
    FlushChunk --> CalcOverlap[计算重叠token数<br/>overlap_tokens = <br/>chunk_token_num * overlapped_percent]
    
    CalcOverlap --> FindOverlapStart[从后向前遍历current_chunk<br/>找到overlap_tokens起始位置]
    
    FindOverlapStart --> StartNew[开始新chunk:<br/>从重叠起始位置开始]
    
    StartNew --> AddCurrent[添加当前段落到新chunk]
    
    AddToChunk --> NextSection{还有段落?}
    AddCurrent --> NextSection
    
    NextSection -->|是| LoopSections
    NextSection -->|否| FlushFinal[输出最后一个chunk]
    
    FlushFinal --> JoinChunks[用delimiter连接<br/>每个chunk内的段落]
    
    JoinChunks --> Return[返回chunks列表]
    Return --> End[结束]
    
    style Start fill:#e1f5ff
    style End fill:#e1f5ff
    style CheckBudget fill:#fff4e1
    style CalcOverlap fill:#ffe1f0
    style JoinChunks fill:#e1ffe1
```

### 参数说明

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `sections` | `list[tuple[str, str]]` | - | 文本段落列表，每个元素为(text, layout_type) |
| `chunk_token_num` | `int` | 512 | 目标chunk的token数量 |
| `delimiter` | `str` | `"\n"` | 段落之间的分隔符 |
| `overlapped_percent` | `float` | 0.0 | 重叠比例（0.0-1.0），例如0.1表示10%重叠 |

### 代码示例

```python
from rag.nlp import naive_merge

sections = [
    ("第一段文本内容", "text"),
    ("第二段文本内容", "text"),
    ("第三段文本内容", "text"),
]

# 基本用法
chunks = naive_merge(sections, chunk_token_num=512, delimiter="\n")
# 返回: ["第一段文本内容\n第二段文本内容", "第三段文本内容"]

# 带重叠
chunks = naive_merge(sections, chunk_token_num=512, delimiter="\n", overlapped_percent=0.1)
# chunk之间会有10%的重叠内容
```

### 使用场景
- 通用文档切片（naive规则）
- 不需要保留文档结构的场景
- 需要固定token数的chunk
- 需要chunk之间有重叠以保持上下文

## 函数2: hierarchical_merge - 层级化合并策略

### 功能说明
基于文档结构的层级化合并策略，保留标题-正文的层级关系。通过bullets_category识别的结构层级，将相同层级的段落合并到对应的上级标题下。

### 流程图

```mermaid
graph TD
    Start[开始: hierarchical_merge] --> Input[输入参数:<br/>- bull层级类型<br/>- sections文本段落列表<br/>- max_token_num最大token数]
    
    Input --> CheckBull{bull类型?}
    
    CheckBull -->|0: 数字列表| Pattern0[识别模式:<br/>1. 2. 3.]
    CheckBull -->|1: 字母列表| Pattern1[识别模式:<br/>a. b. c.]
    CheckBull -->|2: 罗马数字| Pattern2[识别模式:<br/>I. II. III.]
    CheckBull -->|3: 项目符号| Pattern3[识别模式:<br/>• - *]
    CheckBull -->|-1: 无结构| PatternNone[退化为naive_merge]
    
    Pattern0 --> BuildHierarchy
    Pattern1 --> BuildHierarchy
    Pattern2 --> BuildHierarchy
    Pattern3 --> BuildHierarchy
    PatternNone --> CallNaive[调用naive_merge<br/>返回结果]
    
    BuildHierarchy[构建层级树] --> InitTree[初始化根节点]
    
    InitTree --> LoopSections[遍历所有段落]
    
    LoopSections --> CheckPattern{匹配项目符号?}
    
    CheckPattern -->|是| ParseLevel[解析层级:<br/>根据缩进/符号类型]
    CheckPattern -->|否| IsContent[标记为内容段落]
    
    ParseLevel --> CreateNode[创建层级节点:<br/>level, text, children]
    IsContent --> AttachContent[附加到当前节点]
    
    CreateNode --> InsertTree[插入层级树<br/>根据level找到父节点]
    AttachContent --> NextSection1{还有段落?}
    InsertTree --> NextSection2{还有段落?}
    
    NextSection1 -->|是| LoopSections
    NextSection2 -->|是| LoopSections
    NextSection1 -->|否| TraverseTree
    NextSection2 -->|否| TraverseTree
    
    TraverseTree[深度优先遍历层级树] --> CheckTokenBudget{节点内容token数<br/><= max_token_num?}
    
    CheckTokenBudget -->|是| MergeNode[合并节点:<br/>标题 + 子内容]
    CheckTokenBudget -->|否| SplitNode[拆分节点:<br/>保留标题,分割内容]
    
    MergeNode --> OutputChunk[输出一个chunk]
    SplitNode --> OutputMulti[输出多个chunk]
    
    OutputChunk --> NextNode{还有节点?}
    OutputMulti --> NextNode
    
    NextNode -->|是| TraverseTree
    NextNode -->|否| Return[返回chunks列表]
    
    CallNaive --> Return
    Return --> End[结束]
    
    style Start fill:#e1f5ff
    style End fill:#e1f5ff
    style CheckBull fill:#fff4e1
    style BuildHierarchy fill:#ffe1f0
    style TraverseTree fill:#e1fff4
    style CheckTokenBudget fill:#f0e1ff
```

### 参数说明

| 参数 | 类型 | 说明 |
|------|------|------|
| `bull` | `int` | 项目符号类型：0=数字, 1=字母, 2=罗马数字, 3=符号, -1=无结构 |
| `sections` | `list[tuple[str, str]]` | 文本段落列表 |
| `max_token_num` | `int` | 每个chunk的最大token数 |

### bull类型识别示例

```python
from rag.nlp import bullets_category

sections = [
    ("1. 第一章", "title"),
    ("1.1 第一节", "title"),
    ("正文内容", "text"),
    ("2. 第二章", "title"),
]

bull = bullets_category([t for t, _ in sections])
# 返回: 0 (识别为数字列表结构)

chunks = hierarchical_merge(bull, sections, max_token_num=512)
# 返回: [
#   "1. 第一章\n1.1 第一节\n正文内容",
#   "2. 第二章"
# ]
```

### 使用场景
- 结构化文档（book规则）
- 学术论文（paper规则）
- 带有章节标题的文档
- 需要保留文档逻辑结构
- 需要标题-正文对应关系

## 函数3: tokenize_chunks - Chunk Tokenization

### 功能说明
将原始文本chunk转换为最终的chunk文档格式，添加位置信息、图片描述、重要关键词等元数据。

### 流程图

```mermaid
graph TD
    Start[开始: tokenize_chunks] --> Input[输入参数:<br/>- chunks文本列表<br/>- doc文档元数据<br/>- eng分词器<br/>- pdf_parser PDF解析器<br/>- image_proj图片投影模型]
    
    Input --> InitResult[初始化结果列表res]
    
    InitResult --> LoopChunks[遍历chunks]
    
    LoopChunks --> CreateDoc[深拷贝doc<br/>创建新文档对象]
    
    CreateDoc --> SetContent[设置content_with_weight<br/>= chunk文本]
    
    SetContent --> Tokenize[分词: eng.tokenize<br/>存储为tokens_ids]
    
    Tokenize --> ExtractImages{chunk中有图片?}
    
    ExtractImages -->|是| GetImageBlocks[获取图片块列表<br/>从pdf_parser]
    ExtractImages -->|否| ExtractKeywords
    
    GetImageBlocks --> CheckVisionModel{有image_proj<br/>模型?}
    
    CheckVisionModel -->|是| CallVision[调用视觉模型<br/>生成图片描述]
    CheckVisionModel -->|否| UseImageID[仅保存image_id]
    
    CallVision --> AppendDesc[追加描述到chunk文本]
    UseImageID --> StoreImageID[存储image_id字段]
    
    AppendDesc --> ExtractKeywords
    StoreImageID --> ExtractKeywords[提取重要关键词]
    
    ExtractKeywords --> CheckTitle{有标题?}
    CheckTitle -->|是| AddTitleKwd[标题关键词<br/>添加到important_kwd]
    CheckTitle -->|否| CheckFirstSent
    
    AddTitleKwd --> CheckFirstSent{有首句?}
    CheckFirstSent -->|是| AddFirstSent[首句关键词<br/>添加到important_kwd]
    CheckFirstSent -->|否| AddPosition
    
    AddFirstSent --> AddPosition[调用add_positions<br/>添加页码/位置信息]
    
    AddPosition --> AppendResult[添加到结果列表res]
    
    AppendResult --> NextChunk{还有chunk?}
    NextChunk -->|是| LoopChunks
    NextChunk -->|否| Return[返回res]
    
    Return --> End[结束]
    
    style Start fill:#e1f5ff
    style End fill:#e1f5ff
    style ExtractImages fill:#fff4e1
    style CallVision fill:#ffe1f0
    style ExtractKeywords fill:#e1fff4
    style AddPosition fill:#f0e1ff
```

### 输出字段

每个chunk文档对象包含以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `content_with_weight` | `str` | chunk文本内容 |
| `tokens_ids` | `list[int]` | 分词后的token ID列表 |
| `image_id` | `str` | 关联的图片ID（如有） |
| `important_kwd` | `list[str]` | 重要关键词列表 |
| `page_number` | `int` | 页码 |
| `top` | `float` | 页面内Y坐标 |
| `position_int` | `int` | 在文档中的位置索引 |
| `docnm_kwd` | `str` | 文档名称 |

### 代码示例

```python
from rag.nlp import tokenize_chunks, rag_tokenizer

chunks = [
    "第一章 引言\n这是引言内容。",
    "第二章 方法\n这是方法描述。"
]

doc = {
    "docnm_kwd": "example.pdf",
    "kb_id": "kb123"
}

eng = rag_tokenizer.get_tokenizer()

result = tokenize_chunks(chunks, doc, eng)

for chunk_doc in result:
    print(f"内容: {chunk_doc['content_with_weight']}")
    print(f"Token数: {len(chunk_doc['tokens_ids'])}")
    print(f"页码: {chunk_doc.get('page_number')}")
    print(f"关键词: {chunk_doc.get('important_kwd')}")
    print("---")
```

### 使用场景
- 所有chunk规则的最后一步
- 将文本转换为可索引的文档格式
- 添加RAG检索所需的元数据
- 集成视觉模型的图片描述

---

## 函数4: tokenize_table - 表格Tokenization

### 功能说明
表格专用的tokenization函数，处理表格行数据，支持列角色配置（indexing/metadata/both）。

### 流程图

```mermaid
graph TD
    Start[开始: tokenize_table] --> Input[输入参数:<br/>- table表格数据<br/>- doc文档元数据<br/>- eng分词器<br/>- column_roles列角色配置]
    
    Input --> ParseTable[解析表格结构:<br/>headers列名<br/>rows行数据]
    
    ParseTable --> LoopRows[遍历每一行]
    
    LoopRows --> CreateDoc[深拷贝doc<br/>创建新chunk文档]
    
    CreateDoc --> InitFields[初始化:<br/>- text_fields用于向量化<br/>- metadata_fields仅存储]
    
    InitFields --> LoopCols[遍历每一列]
    
    LoopCols --> GetColName[获取列名和值]
    
    GetColName --> LookupRole[查找column_roles<br/>默认: both]
    
    LookupRole --> SwitchRole{角色类型?}
    
    SwitchRole -->|indexing| AddText[仅添加到text_fields]
    SwitchRole -->|metadata| AddMeta[仅添加到metadata_fields]
    SwitchRole -->|both| AddBoth[同时添加到两者]
    SwitchRole -->|vectorize| AddText
    
    AddText --> NextCol1{还有列?}
    AddMeta --> NextCol2{还有列?}
    AddBoth --> NextCol3{还有列?}
    
    NextCol1 -->|是| LoopCols
    NextCol2 -->|是| LoopCols
    NextCol3 -->|是| LoopCols
    NextCol1 -->|否| BuildContent
    NextCol2 -->|否| BuildContent
    NextCol3 -->|否| BuildContent
    
    BuildContent[构建content_with_weight:<br/>仅包含text_fields]
    
    BuildContent --> TokenizeText[分词text_fields<br/>存储tokens_ids]
    
    TokenizeText --> StoreMeta[存储metadata_fields<br/>为_kwd/_tks字段]
    
    StoreMeta --> SetPosition[设置position_int<br/>= 行号]
    
    SetPosition --> AppendResult[添加到结果列表]
    
    AppendResult --> NextRow{还有行?}
    NextRow -->|是| LoopRows
    NextRow -->|否| Return[返回chunk列表]
    
    Return --> End[结束]
    
    style Start fill:#e1f5ff
    style End fill:#e1f5ff
    style SwitchRole fill:#fff4e1
    style BuildContent fill:#e1ffe1
    style StoreMeta fill:#ffe1f0
```

### 列角色说明

| 角色 | 向量化 | 存储为字段 | 典型用途 |
|------|--------|-----------|---------|
| `indexing` / `vectorize` | ✅ | ❌ | 用于搜索的长文本（描述、备注） |
| `metadata` | ❌ | ✅ | ID、标签、分类等元数据 |
| `both` (默认) | ✅ | ✅ | 标题、名称等需要搜索和显示的字段 |

### 代码示例

```python
from rag.nlp import tokenize_table

table = {
    "headers": ["产品ID", "产品名称", "描述", "价格"],
    "rows": [
        ["P001", "产品A", "这是产品A的详细描述", "99.9"],
        ["P002", "产品B", "这是产品B的详细描述", "199.9"],
    ]
}

doc = {"docnm_kwd": "products.xlsx"}
eng = rag_tokenizer.get_tokenizer()

column_roles = {
    "产品ID": "metadata",      # 仅存储，不参与检索
    "产品名称": "both",        # 既检索又存储
    "描述": "indexing",        # 仅检索，不存储
    "价格": "metadata"         # 仅存储
}

chunks = tokenize_table(table, doc, eng, column_roles)

# 每行生成一个chunk
for chunk in chunks:
    print(chunk["content_with_weight"])
    # 输出: 产品名称: 产品A\n描述: 这是产品A的详细描述
    print(chunk.get("产品ID_kwd"))  # P001 (metadata字段)
```

### 使用场景
- Table规则的最后一步
- Excel/CSV表格解析
- 需要列级别索引控制
- 结构化数据导入RAG系统

## 函数5: naive_merge_docx - DOCX朴素合并

### 功能说明
DOCX文档专用的朴素合并函数，考虑DOCX特有的段落样式和格式信息。

### 流程图

```mermaid
graph TD
    Start[开始: naive_merge_docx] --> Input[输入参数:<br/>- docx_sections DOCX段落<br/>- chunk_token_num目标token数<br/>- delimiter分隔符]
    
    Input --> CheckFormat{段落格式?}
    
    CheckFormat -->|纯文本| UsePlainText[提取纯文本内容]
    CheckFormat -->|富文本| ParseStyle[解析样式信息:<br/>- 标题级别<br/>- 字体/颜色<br/>- 列表标记]
    
    UsePlainText --> MergeLogic
    ParseStyle --> PreserveStyle[保留样式标记<br/>在文本中]
    
    PreserveStyle --> MergeLogic[应用朴素合并逻辑]
    
    MergeLogic --> InitChunk[初始化当前chunk]
    
    InitChunk --> LoopSections[遍历DOCX段落]
    
    LoopSections --> CheckStyle{是标题?}
    
    CheckStyle -->|是| ForceBreak[强制断开chunk<br/>标题作为新chunk开头]
    CheckStyle -->|否| CheckBudget{token预算<br/>是否充足?}
    
    ForceBreak --> StartNewChunk[输出当前chunk<br/>开始新chunk]
    
    CheckBudget -->|是| AddToChunk[添加到当前chunk]
    CheckBudget -->|否| FlushChunk[输出当前chunk<br/>开始新chunk]
    
    AddToChunk --> NextSection1{还有段落?}
    FlushChunk --> AddCurrent[添加当前段落到新chunk]
    StartNewChunk --> AddTitle[添加标题到新chunk]
    
    AddCurrent --> NextSection2{还有段落?}
    AddTitle --> NextSection3{还有段落?}
    
    NextSection1 -->|是| LoopSections
    NextSection2 -->|是| LoopSections
    NextSection3 -->|是| LoopSections
    NextSection1 -->|否| OutputFinal
    NextSection2 -->|否| OutputFinal
    NextSection3 -->|否| OutputFinal
    
    OutputFinal[输出最后一个chunk] --> JoinDelimiter[用delimiter连接段落]
    
    JoinDelimiter --> Return[返回chunks列表]
    Return --> End[结束]
    
    style Start fill:#e1f5ff
    style End fill:#e1f5ff
    style CheckFormat fill:#fff4e1
    style CheckStyle fill:#ffe1f0
    style MergeLogic fill:#e1ffe1
```

### 与naive_merge的区别

| 特性 | naive_merge | naive_merge_docx |
|------|-------------|------------------|
| 输入类型 | 通用文本段落 | DOCX段落对象 |
| 样式处理 | 无 | 保留标题/列表样式 |
| 断开策略 | 仅token预算 | token预算 + 标题强制断开 |
| 应用场景 | 通用文档 | DOCX专用 |

### 代码示例

```python
from rag.nlp import naive_merge_docx
from docx import Document

doc = Document("example.docx")
docx_sections = []

for para in doc.paragraphs:
    docx_sections.append({
        "text": para.text,
        "style": para.style.name,  # 'Heading 1', 'Normal', etc.
        "is_heading": para.style.name.startswith('Heading')
    })

chunks = naive_merge_docx(
    docx_sections,
    chunk_token_num=512,
    delimiter="\n"
)

# 标题会作为chunk的开始
# 例如: ["Heading 1\n段落1\n段落2", "Heading 2\n段落3"]
```

### 使用场景
- DOCX文档解析
- 需要保留Word文档格式信息
- 标题需要作为chunk边界
- Office文档导入RAG系统

## 函数6: add_positions - 添加位置信息

### 功能说明
为chunk添加页码和在页面内的位置信息，用于检索结果的溯源定位。

### 流程图

```mermaid
graph TD
    Start[开始: add_positions] --> Input[输入参数:<br/>- chunks chunk文档列表<br/>- pdf_parser PDF解析器]
    
    Input --> GetPages[从pdf_parser获取<br/>页面信息列表]
    
    GetPages --> LoopChunks[遍历每个chunk]
    
    LoopChunks --> GetContent[获取chunk文本内容]
    
    GetContent --> SearchPages[在页面列表中查找<br/>包含该内容的页面]
    
    SearchPages --> LoopPages[遍历每一页]
    
    LoopPages --> ExtractPageText[提取页面全文]
    
    ExtractPageText --> CheckContains{页面文本<br/>包含chunk内容?}
    
    CheckContains -->|否| NextPage{还有页面?}
    CheckContains -->|是| CalcPosition[计算位置信息]
    
    NextPage -->|是| LoopPages
    NextPage -->|否| NoPosition[未找到位置<br/>使用默认值]
    
    CalcPosition --> FindOffset[在页面文本中<br/>查找内容偏移量]
    
    FindOffset --> CalcTop[根据偏移量<br/>计算Y坐标top]
    
    CalcTop --> SetFields[设置字段:<br/>- page_number页码<br/>- top Y坐标<br/>- position_int全局位置]
    
    NoPosition --> SetDefaults[设置默认值:<br/>page_number=0<br/>top=0<br/>position_int=索引]
    
    SetFields --> NextChunk1{还有chunk?}
    SetDefaults --> NextChunk2{还有chunk?}
    
    NextChunk1 -->|是| LoopChunks
    NextChunk2 -->|是| LoopChunks
    NextChunk1 -->|否| Return
    NextChunk2 -->|否| Return
    
    Return[返回更新后的chunks] --> End[结束]
    
    style Start fill:#e1f5ff
    style End fill:#e1f5ff
    style SearchPages fill:#fff4e1
    style CalcPosition fill:#e1ffe1
    style SetFields fill:#ffe1f0
```

### 输出字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `page_number` | `int` | 页码（从1开始），0表示未找到 |
| `top` | `float` | 在页面内的Y坐标（PDF points），从页面顶部开始 |
| `position_int` | `int` | 在整个文档中的位置索引（全局顺序） |

## 性能对比

| 函数 | 时间复杂度 | 空间复杂度 | 适用文档大小 | 备注 |
|------|-----------|-----------|-------------|------|
| `naive_merge` | O(n) | O(1) | 任意 | 最快，线性扫描 |
| `hierarchical_merge` | O(n log n) | O(n) | <10MB | 需要构建层级树 |
| `tokenize_chunks` | O(n*m) | O(n) | 任意 | m为平均chunk长度 |
| `tokenize_table` | O(r*c) | O(r) | <100K行 | r行c列 |
| `naive_merge_docx` | O(n) | O(1) | 任意 | 类似naive_merge |
| `add_positions` | O(n*p) | O(1) | 任意 | p为页数 |

## 最佳实践

### 1. 选择合适的合并策略
- **通用文档**: 优先使用`naive_merge`，简单高效
- **结构化文档**: 使用`hierarchical_merge`保留层级关系
- **DOCX文档**: 使用`naive_merge_docx`保留样式信息
- **表格数据**: 直接使用`tokenize_table`，不需要预合并
