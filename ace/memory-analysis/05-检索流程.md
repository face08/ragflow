# RAGFlow Memory 模块 — 检索流程

## 1. 检索场景总览

Memory 模块支持两类检索操作：

| 操作 | 接口 | 用途 | 返回 |
|------|------|------|------|
| 语义检索 | `GET /v1/memory/{id}/query` | 根据查询向量找相似记忆 | 匹配的消息列表（带相关度） |
| 消息列表 | `GET /v1/memory/{id}/messages` | 分页浏览所有消息 | 原始消息 + 关联的提取记忆 |

两者的核心区别：
- **语义检索**：混合向量相似度 + BM25 文本匹配，用于 RAG 增强和上下文注入
- **消息列表**：按时间倒序分页，用于前端展示对话历史

## 2. 语义检索流程

### 2.1 查询向量化

使用 Memory 配置的嵌入模型向量化查询文本：

```go
// internal/service/memory.go: queryMessage
func (s *MemoryService) QueryMessage(
    ctx context.Context, memoryID, query string, topK int,
) ([]map[string]interface{}, error) {
    // 权限检查
    memory, err := s.requireMemoryAccess(ctx, memoryID, userID)
    if err != nil {
        return nil, err
    }
    
    // 向量化查询
    embedding, err := s.embeddingClient.Embed(ctx, &EmbedRequest{
        Model: memory.EmbdModel.Name,
        Input: query,
    })
    if err != nil {
        return nil, err
    }
    
    // 构建混合检索请求
    results, err := s.hybridSearch(ctx, memory, embedding, query, topK)
    return results, err
}
```

### 2.2 混合检索策略

结合向量相似度和关键词匹配，提升召回率：

```go
// internal/service/memory.go: hybridSearch
func (s *MemoryService) hybridSearch(
    ctx context.Context, memory *entity.Memory,
    queryVec []float32, queryText string, topK int,
) ([]map[string]interface{}, error) {
    indexName := fmt.Sprintf("memory_%s", memory.TenantID)
    if docStore.EngineType() == "infinity" {
        indexName = fmt.Sprintf("%s_%s", indexName, memory.ID)
    }
    
    vectorField := fmt.Sprintf("q_%d_vec", len(queryVec))
    
    // 文本权重：keyword_similarity / 2
    textWeight := 0.5
    vectorWeight := 1 - textWeight
    
    searchReq := &SearchRequest{
        IndexName: indexName,
        Filter: map[string]interface{}{
            "memory_id": memory.ID,
            "forget_at": 0,  // 只检索未遗忘的记忆
        },
        VectorField: vectorField,
        QueryVector: queryVec,
        QueryText:   queryText,
        Fusion: &FusionExpr{
            Method:  "weighted_sum",
            TopN:    topK,
            Weights: fmt.Sprintf("%.2f,%.2f", textWeight, vectorWeight),
        },
    }
    
    return docStore.Search(ctx, searchReq)
}
```

### 2.3 Fusion 表达式

不同文档引擎的实现：

**Elasticsearch:**
```json
{
  "query": {
    "script_score": {
      "query": {"match": {"content": "query text"}},
      "script": {
        "source": "_score * 0.5 + cosineSimilarity(params.query_vec, 'q_1024_vec') * 0.5"
      }
    }
  }
}
```

**Infinity:**
```python
fusion_expr = f"weighted_sum({text_weight}, {vector_weight})"
```

权重设计原则：文本权重设为 `keyword_similarity / 2`，确保高质量的关键词匹配不会被向量相似度完全压制。

### 2.4 过滤条件

检索时自动应用的过滤：

| 过滤条件 | 值 | 说明 |
|----------|-----|------|
| memory_id | memory.ID | 限定在当前 Memory 范围内 |
| forget_at | 0 | 排除已遗忘的消息 |
| tenant_id | memory.TenantID | 多租户隔离（索引级别已保证） |

可选过滤（用户传入）：

| 参数 | 字段 | 用途 |
|------|------|------|
| session_id | session_id | 按会话过滤 |
| user_id | user_id | 多用户记忆隔离 |
| memory_type | memory_type | 只检索特定类型（原始/语义/情景/程序） |

## 3. 消息列表流程

### 3.1 两阶段查询

消息列表展示需要将提取记忆关联到原始消息下，采用两阶段查询：

```
  阶段 1：查询原始消息（分页）
           ▼
  阶段 2：批量查询提取记忆（source_id IN raw_ids）
           ▼
       组装嵌套结构返回
```

### 3.2 阶段 1：查询原始消息

```go
// internal/service/memory.go: listMemoryMessages
func (s *MemoryService) ListMemoryMessages(
    ctx context.Context, memoryID string, page, pageSize int,
) ([]map[string]interface{}, error) {
    memory, err := s.requireMemoryAccess(ctx, memoryID, userID)
    if err != nil {
        return nil, err
    }
    
    indexName := getIndexName(memory)
    
    // 只查原始消息
    rawReq := &SearchRequest{
        IndexName: indexName,
        Filter: map[string]interface{}{
            "memory_id":   memoryID,
            "memory_type": MemoryTypeRaw,  // 0b0001
            "forget_at":   0,
        },
        Sort: []SortField{
            {Field: "create_time", Order: "desc"},
        },
        Page:     page,
        PageSize: pageSize,
    }
    
    rawMessages, err := docStore.Search(ctx, rawReq)
    if err != nil {
        return nil, err
    }
    
    if len(rawMessages) == 0 {
        return []map[string]interface{}{}, nil
    }
    
    // 收集原始消息 ID
    rawIDs := make([]string, len(rawMessages))
    for i, msg := range rawMessages {
        rawIDs[i] = msg["id"].(string)
    }
    
    // 进入阶段 2
    extracts := s.fetchExtractsBySourceIDs(ctx, memory, rawIDs)
    return s.mergeMessagesWithExtracts(rawMessages, extracts), nil
}
```

### 3.3 阶段 2：批量查询提取记忆

```go
// internal/service/memory.go: fetchExtractsBySourceIDs
func (s *MemoryService) fetchExtractsBySourceIDs(
    ctx context.Context, memory *entity.Memory, rawIDs []string,
) []map[string]interface{} {
    // 限制单次查询的 ID 数量，防止超出引擎限制
    const maxIDsPerQuery = 512
    if len(rawIDs) > maxIDsPerQuery {
        rawIDs = rawIDs[:maxIDsPerQuery]
    }
    
    indexName := getIndexName(memory)
    
    extractReq := &SearchRequest{
        IndexName: indexName,
        Filter: map[string]interface{}{
            "memory_id":   memory.ID,
            "memory_type": map[string]interface{}{
                "ne": MemoryTypeRaw,  // 非原始消息，即提取记忆
            },
            "source_id": map[string]interface{}{
                "in": rawIDs,  // IN 查询
            },
            "forget_at": 0,
        },
        Size: len(rawIDs) * 10,  // 预估每条原始消息可能有多条提取
    }
    
    results, err := docStore.Search(ctx, extractReq)
    if err != nil {
        log.Error("fetch extracts failed", "error", err)
        return []map[string]interface{}{}
    }
    
    return results
}
```

关键设计：
- **IN 查询限制**：单次最多 512 个 ID，超出部分截断（分页场景下足够）
- **预估容量**：`len(rawIDs) * 10`，假设每条原始消息平均提取 10 条记忆

### 3.4 组装嵌套结构

```go
// internal/service/memory.go: mergeMessagesWithExtracts
func (s *MemoryService) mergeMessagesWithExtracts(
    rawMessages []map[string]interface{},
    extracts []map[string]interface{},
) []map[string]interface{} {
    // 按 source_id 分组提取记忆
    extractMap := make(map[string][]map[string]interface{})
    for _, ext := range extracts {
        sourceID := ext["source_id"].(string)
        extractMap[sourceID] = append(extractMap[sourceID], ext)
    }
    
    // 将提取记忆挂到原始消息下
    for i := range rawMessages {
        rawID := rawMessages[i]["id"].(string)
        if exts, ok := extractMap[rawID]; ok {
            rawMessages[i]["extracts"] = exts
        } else {
            rawMessages[i]["extracts"] = []map[string]interface{}{}
        }
    }
    
    return rawMessages
}
```

## 4. 按类型检索

### 4.1 记忆类型过滤

用户可以指定只检索特定类型的记忆：

```go
// 只检索语义记忆
filter["memory_type"] = MemoryTypeSemantic  // 0b0010

// 检索语义 + 情景记忆
filter["memory_type"] = MemoryTypeSemantic | MemoryTypeEpisodic  // 0b0110
```

实际查询需要转换为文档引擎支持的语法：

**Elasticsearch:**
```json
{
  "query": {
    "bool": {
      "filter": [
        {"term": {"memory_type": 2}}
      ]
    }
  }
}
```

**位运算匹配（如果引擎支持）：**
```go
// 检查 memory_type 是否包含某个位
filter["memory_type"] = map[string]interface{}{
    "bitwise_and": MemoryTypeSemantic,
    "ne": 0,
}
```

### 4.2 时间范围过滤

提取记忆带有 `valid_at` 和 `invalid_at` 时间戳，支持时间范围查询：

```go
// 查询当前有效的记忆
now := time.Now().Format(time.RFC3339)
filter["valid_at"] = map[string]interface{}{"lte": now}
filter["invalid_at"] = map[string]interface{}{
    "or": []interface{}{
        nil,                           // invalid_at 为空
        map[string]interface{}{"gt": now},  // 或未过期
    },
}
```

## 5. 性能优化

### 5.1 索引策略

| 字段 | 索引类型 | 用途 |
|------|----------|------|
| memory_id | keyword | 高频过滤字段，必须索引 |
| memory_type | integer | 类型过滤 |
| forget_at | long | 遗忘过滤，0 值特殊处理 |
| create_time | long | 排序字段 |
| q_1024_vec | dense_vector | 向量检索 |
| content | text | 全文检索 |

### 5.2 缓存层

Redis 缓存热点数据：

| 缓存键 | 值 | TTL | 用途 |
|--------|-----|-----|------|
| `memory_<memory_id>` | 累计消息字节数 | 无限 | 快速检查配额 |
| `memory_config_<memory_id>` | Memory 配置 JSON | 5 分钟 | 减少数据库查询 |

### 5.3 批量查询优化

消息列表的两阶段查询中，阶段 2 使用 `source_id IN (...)` 批量查询，避免 N+1 问题。

限制：
- 单次 IN 查询最多 512 个 ID
- 如果单页返回超过 512 条原始消息，提取记忆会被截断（实际场景极少）

## 6. Python 侧实现对照

```python
# memory/services/query.py
async def query_message(memory_id: str, query: str, top_k: int) -> List[Dict]:
    memory = MemoryService.get_by_id(memory_id)
    
    # 向量化查询
    embedding = await embedding_client.embed(query, memory.embd_model)
    
    # 混合检索
    index_name = f"memory_{memory.tenant_id}"
    text_weight = 0.5
    vector_weight = 1 - text_weight
    
    results = doc_store.search(
        index_name=index_name,
        query_vector=embedding,
        query_text=query,
        filter={"memory_id": memory_id, "forget_at": 0},
        fusion=FusionExpr(
            method="weighted_sum",
            top_n=top_k,
            weights=f"{text_weight},{vector_weight}"
        )
    )
    
    return results
```

Go 和 Python 侧共享同一套索引和检索逻辑。
