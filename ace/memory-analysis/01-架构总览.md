# RAGFlow Memory 模块架构总览

## 1. 概述

RAGFlow 的 Memory 模块是一个持久化对话记忆系统，用于在多轮对话中保存和检索重要信息。该模块采用双运行时架构（Python + Go），支持多种记忆类型，并通过异步 LLM 提取管道实现智能记忆生成。

## 2. 核心架构

### 2.1 双运行时设计

Memory 模块同时使用 Python 和 Go 实现，两者功能保持同步：

- **Python 侧**：
  - 基于 Quart 的异步 API 服务器
  - Peewee ORM 数据访问层
  - 异步任务队列处理

- **Go 侧**：
  - 基于 Gin 的 HTTP 处理器
  - GORM 数据访问层
  - 租户权限模型
  - 内存管理和检索服务

## 3. 核心数据模型

### 3.1 Memory 表

Memory 是记忆实例的主表，存储记忆配置和元数据：

| 字段 | 类型 | 说明 |
|-----|------|-----|
| id | string | 记忆唯一标识符 |
| tenant_id | string | 所属租户 ID |
| name | string | 记忆名称 |
| description | string | 记忆描述 |
| memory_type | int | 记忆类型（位标志） |
| storage_type | string | 存储类型（默认 "table"） |
| memory_size | int | 记忆大小限制（字节） |
| forgetting_policy | string | 遗忘策略（"FIFO"） |
| tenant_llm_id | string | 租户 LLM ID |
| llm_id | string | LLM 模型 ID |
| tenant_embd_id | string | 租户嵌入模型 ID |
| embd_id | string | 嵌入模型 ID |
| temperature | float | LLM 温度参数（默认 0.5） |
| system_prompt | string | 系统提示词 |
| permissions | string | 访问权限（me/team/all） |
| create_time | datetime | 创建时间 |
| update_time | datetime | 更新时间 |
| create_date | date | 创建日期 |
| update_date | date | 更新日期 |

**记忆类型位标志**：

```go
const (
    MemoryTypeRaw        = 0b0001  // 原始消息
    MemoryTypeSemantic   = 0b0010  // 语义记忆（通用事实）
    MemoryTypeEpisodic   = 0b0100  // 情景记忆（具体事件）
    MemoryTypeProcedural = 0b1000  // 程序记忆（步骤流程）
)
```

### 3.2 MemoryTask 表

MemoryTask 存储异步提取任务的持久化状态：

| 字段 | 类型 | 说明 |
|-----|------|-----|
| task_id | string | 关联的 Task ID（主键） |
| memory_id | string | 所属记忆 ID |
| source_id | string | 原始消息 ID |
| input | JSONMap | 输入数据（user_input, agent_response） |
| state | string | 任务状态 |
| extraction | JSONSlice | 提取结果 JSON 数组 |
| next_retry_at | datetime | 下次重试时间 |
| attempt_count | int | 尝试次数 |
| lease_owner | string | 租约持有者标识 |
| lease_expires_at | datetime | 租约过期时间 |
| last_error | string | 最后错误信息 |

**任务状态**：

- `pending`: 待处理
- `extracted`: 已提取（进度 0.5）
- `stored`: 已存储到索引
- `completed`: 完成（进度 1.0）
- `failed`: 失败（进度 -1）

### 3.3 Task 表

通用任务表，跟踪所有类型任务的进度：

| 字段 | 类型 | 说明 |
|-----|------|-----|
| id | string | 任务 ID |
| doc_id | string | 文档 ID（对于 memory 是 memory_id） |
| task_type | string | 任务类型（"memory"） |
| progress | float | 进度（-1=失败, 0-1=进行中/完成） |
| digest | string | 摘要信息（存储 raw_message_id） |

## 4. 记忆类型与用途

### 4.1 Raw Memory（原始记忆）

- **标志位**: `0b0001`
- **用途**: 存储原始对话内容，不经过 LLM 提取
- **格式**: `"User Input: {user}\nAgent Response: {agent}"`
- **特点**: 直接保存，无需异步处理

### 4.2 Semantic Memory（语义记忆）

- **标志位**: `0b0010`
- **用途**: 存储通用事实、知识和概念
- **提取指令**: "永恒真理、通用知识、可跨场景应用的信息"
- **示例**: 用户偏好、技能特长、事实性知识

### 4.3 Episodic Memory（情景记忆）

- **标志位**: `0b0100`
- **用途**: 存储具体事件、经历和场景
- **提取指令**: "具体发生的事件、带时间和地点的经历"
- **字段**: 包含 `valid_at`（有效期开始）、`invalid_at`（有效期结束）
- **示例**: 会议记录、项目进展、特定日期的活动

### 4.4 Procedural Memory（程序记忆）

- **标志位**: `0b1000`
- **用途**: 存储步骤流程、操作方法
- **提取指令**: "如何做某事的步骤、操作流程、方法论"
- **示例**: 工作流程、解决问题的步骤、操作指南

## 5. 权限模型

Memory 模块支持基于租户的多级权限控制：

### 5.1 访问权限级别

- **me**: 仅创建者可访问
- **team**: 同租户成员可访问
- **all**: 所有人可访问（跨租户）

### 5.2 权限过滤逻辑

```go
// 访问检查流程
1. 检查用户是否属于 memory 的租户
2. 根据 permissions 字段判断：
   - "me": 仅 memory.tenant_id == user.tenant_id 且创建者匹配
   - "team": memory.tenant_id IN (user.joined_tenants)
   - "all": 无限制
3. 列表查询时自动过滤不可访问的记忆
```

## 6. 索引与检索

### 6.1 索引命名规范

- **Elasticsearch/OceanBase/GaussDB**: `memory_{tenant_id}`
- **Infinity**: `memory_{tenant_id}_{memory_id}`
- **前缀**: 支持通过 `ES_INDEX_PREFIX` 环境变量添加全局前缀

### 6.2 文档 ID 格式

```
{memory_id}_{message_id}
```

示例: `mem_123abc_msg_456def`

### 6.3 混合检索策略

Memory 检索采用文本 + 向量的融合检索：

```python
# 融合表达式
FusionExpr(
    method="weighted_sum",
    top_n=top_k,
    weights=f"{text_weight},{1-text_weight}"
)
```

**权重计算**：
- `text_weight = keyword_similarity / 2`
- `vector_weight = 1 - text_weight`
- 默认情况下文本和向量权重各占 50%

**检索流程**：
1. BM25 风格的文本搜索（TopN 100）
2. 余弦相似度的向量搜索
3. 加权融合排序
4. 返回 TopK 结果

## 8. 技术特性

### 8.1 分布式任务协调

- **租约机制**: 使用数据库租约防止多个 worker 同时处理同一任务
- **SELECT FOR UPDATE**: 原子性地声明任务所有权
- **租约续期**: Worker 每 30 秒续期一次，确保活跃性
- **租约过期**: 2 分钟未续期的任务可被其他 worker 接管

### 8.2 容错与重试

- **指数退避**: 重试间隔从 5 秒增长到 5 分钟
- **永久失败检测**: 某些错误（如配置错误）标记为永久失败，不再重试
- **最大尝试次数**: 10 次尝试后标记为永久失败
- **状态持久化**: 每个状态转换都持久化到数据库

### 8.3 记忆大小配额

- **实时统计**: Redis 缓存 `memory_{memory_id}` 存储当前大小
- **FIFO 淘汰**: 超过配额时删除最早的消息
- **软删除**: 通过 `forget_at` 时间戳实现软删除
- **批量淘汰**: `pickMessagesToEvict` 选择待删除消息

### 8.4 提示词组装

- **类型化指令**: 每种记忆类型有专门的提取指令
- **输出模板**: JSON 格式 `{content, valid_at?, invalid_at?}`
- **时间戳格式**: ISO 8601
- **默认检测**: `is_default_system_prompt` 检测是否使用默认提示词
