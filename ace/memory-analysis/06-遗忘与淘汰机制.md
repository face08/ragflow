# 06 - 遗忘与淘汰机制

## 1. 概述

RAGFlow Memory 模块提供两种主动删除记忆的机制：

1. **软删除（Forget）**：用户主动标记消息为"已遗忘"，通过设置 `forget_at` 时间戳实现
2. **自动淘汰（Eviction）**：当存储空间达到配额上限时，根据淘汰策略（默认 FIFO）自动删除旧记忆

两者的本质区别：
- Forget 是**标记式删除**，记录保留但在检索时被过滤
- Eviction 是**物理删除**，记录从索引和任务表中彻底移除

## 2. 软删除流程

### 2.1 触发路径

```
用户请求 → API 层 → ForgetMessage 服务 → 更新 forget_at 字段
```

### 2.2 Go 侧实现

```go
// internal/service/memory.go
func (s *MemoryService) ForgetMessage(
    ctx context.Context,
    userID string,
    memoryID string,
    messageID int64,
) error {
    // 1. 权限检查
    memory, err := s.requireMemoryAccess(ctx, userID, memoryID)
    if err != nil {
        return err
    }

    // 2. 生成遗忘时间戳（服务器本地时区）
    now := memoryNow()  // time.Now()
    forgetTime := now.Format("2006-01-02 15:04:05")

    // 3. 构造更新字段
    messageDocID := fmt.Sprintf("%s_%d", memoryID, messageID)
    updates := map[string]interface{}{
        "forget_at": forgetTime,  // 字符串格式，用于 Elasticsearch 显示
    }

    // 4. 添加毫秒时间戳（仅非 OceanBase 引擎）
    if !engine.IsOceanBaseFamily(s.docEngine.GetType()) {
        updates["forget_at_flt"] = now.UnixMilli()  // 用于高效排序和过滤
    }

    // 5. 更新文档
    condition := map[string]interface{}{"id": messageDocID}
    indexName := memoryIndexName(memory.TenantID)
    err = s.docEngine.UpdateChunks(ctx, condition, updates, indexName, memoryID)

    // 6. 幂等性处理：消息不存在视为成功
    if err != nil && isMessageDocumentNotFound(err) {
        return nil
    }
    return err
}
```

### 2.3 Python 侧实现

```python
# api/apps/services/memory_api_service.py
async def forget_message(memory_id: str, message_id: int):
    memory = _require_memory_access(memory_id)
    
    # 生成遗忘时间戳
    forget_time = timestamp_to_date(current_timestamp())
    
    # 更新文档
    update_succeed = MessageService.update_message(
        {"memory_id": memory_id, "message_id": int(message_id)},
        {"forget_at": forget_time},
        memory.tenant_id,
        memory_id
    )
    
    if not update_succeed:
        raise Exception(f"Failed to forget message '{message_id}' in memory '{memory_id}'.")
```

### 2.4 字段说明

| 字段 | 类型 | 用途 |
|------|------|------|
| `forget_at` | string | 遗忘时间（本地时区格式 `2006-01-02 15:04:05`），用于用户可读显示 |
| `forget_at_flt` | int64 | 遗忘时间的毫秒时间戳（UTC），用于高效过滤和排序 |

**注意**：
- OceanBase 引擎只支持 `forget_at` 字符串字段
- Elasticsearch/Infinity 引擎同时维护两个字段
- 检索时优先使用 `forget_at_flt` 进行数值过滤（性能更好）

### 2.5 检索过滤逻辑

所有检索操作默认排除已遗忘消息：

```go
// 语义检索
filter := map[string]interface{}{
    "memory_id": memoryID,
    "forget_at": 0,  // 排除非零值（即已设置 forget_at 的记录）
}

// 消息列表查询

    "memory_type": MemoryTypeRaw,

```

Python 侧使用 Elasticsearch DSL：

```python

    "exists": "forget_at"
}
```

## 3. 自动淘汰流程

### 3.1 触发时机

在 `embed_and_save` 写入新消息前，检查配额：

```
新消息大小 + 当前内存大小 > memory.memory_size
    ↓
触发淘汰策略
```

### 3.2 配额计算

#### Redis 缓存机制

系统通过 Redis 缓存每个 Memory 的当前大小，避免每次写入时全量统计：

```python
# api/db/joint_services/memory_message_service.py
def get_memory_size_cache(memory_id: str, uid: str):
    redis_key = f"memory_{memory_id}"
    if REDIS_CONN.exist(redis_key):
        return int(REDIS_CONN.get(redis_key))
    else:
        # 缓存未命中，从索引全量统计并写入缓存
        memory_size_map = MessageService.calculate_memory_size([memory_id], [uid])
        memory_size = memory_size_map.get(memory_id, 0)
        set_memory_size_cache(memory_id, memory_size)
        return memory_size

def increase_memory_size_cache(memory_id: str, size: int):
    redis_key = f"memory_{memory_id}"
    return REDIS_CONN.incrby(redis_key, size)  # 原子增加

def decrease_memory_size_cache(memory_id: str, size: int):
    redis_key = f"memory_{memory_id}"
    return REDIS_CONN.decrby(redis_key, size)  # 原子减少
```

#### 消息大小计算

```python
# memory/services/messages.py
@classmethod
def calculate_message_size(message: dict):
    # 内容大小
    content_size = sys.getsizeof(message.get("content", ""))
    
    # 向量大小
    content_embed = message.get("content_embed")
    if content_embed and len(content_embed) > 0:
        embed_size = sys.getsizeof(content_embed[0]) * len(content_embed)
    else:
        embed_size = 0
    
    return content_size + embed_size
```

### 3.3 FIFO 淘汰策略

当前唯一支持的策略是 **FIFO（First-In-First-Out）**。

#### 选择逻辑

```python
# memory/services/messages.py
@classmethod
def pick_messages_to_delete_by_fifo(cls, memory_id: str, uid: str, size_to_delete: int):
    """
    选择待删除的消息 ID，直到累计大小满足 size_to_delete。
    
    优先级：
    1. 已遗忘的消息（forget_at 已设置）
    2. 最早的活跃消息（按 valid_at 升序）
    """
    select_fields = ["message_id", "content", "content_embed"]
    _index_name = index_name(uid)
    
    # 第一阶段：选择已遗忘的消息
    res = settings.msgStoreConn.get_forgotten_messages(select_fields, _index_name, memory_id)
    current_size = 0
    ids_to_remove = []
    
    if res is not None:
        message_list = settings.msgStoreConn.get_fields(res, select_fields)
        for message in message_list.values():
            if current_size < size_to_delete:
                current_size += cls.calculate_message_size(message)
                ids_to_remove.append(message["message_id"])
            else:
                return ids_to_remove, current_size
    
    # 如果已遗忘消息不够，继续选择最早的活跃消息
    if current_size < size_to_delete:
        order_by = OrderByExpr()
        order_by.asc("valid_at")  # 按创建时间升序（最早的先删）
        
        res, total_count = settings.msgStoreConn.search(
            select_fields=select_fields,
            condition={},
            match_expressions=[],
            order_by=order_by,
            offset=0,
            limit=512,  # 最多扫描 512 条
            index_names=[_index_name],
            memory_ids=[memory_id],
        )
        
        docs = settings.msgStoreConn.get_fields(res, select_fields)
        for doc in docs.values():
            if current_size < size_to_delete:
                current_size += cls.calculate_message_size(doc)
                ids_to_remove.append(doc["message_id"])
            else:
                break
    
    return ids_to_remove, current_size
```

#### 关键特性

1. **两阶段选择**：
   - 阶段 1：优先清理已标记遗忘的消息
   - 阶段 2：如果不够，按 `valid_at` 升序选择最早的活跃消息

2. **贪心算法**：
   - 逐条累加消息大小，直到满足 `size_to_delete`
   - 可能删除的总大小 < 请求大小（剩余候选不足）

3. **限制**：
   - 单次最多扫描 512 条消息
   - 如果 Memory 存在大量小消息，可能需要多轮淘汰

### 3.4 完整淘汰流程

```python
# api/db/joint_services/memory_message_service.py
async def embed_and_save(memory, message_list: list[dict], task_id: str = None):
    # 1. 计算新消息总大小
    new_msg_size = sum([MessageService.calculate_message_size(m) for m in message_list])
    
    # 2. 获取当前内存使用量（从 Redis 缓存）
    current_memory_size = get_memory_size_cache(memory.id, memory.tenant_id)
    
    # 3. 判断是否超出配额
    if new_msg_size + current_memory_size > memory.memory_size:
        size_to_delete = current_memory_size + new_msg_size - memory.memory_size
        
        # 4. 根据策略选择待删除消息
        if memory.forgetting_policy == "FIFO":
            message_ids_to_delete, delete_size = MessageService.pick_messages_to_delete_by_fifo(
                memory.id, memory.tenant_id, size_to_delete
            )
            
            # 5. 物理删除消息
            MessageService.delete_message(
                {"message_id": message_ids_to_delete},
                memory.tenant_id,
                memory.id
            )
            
            # 6. 更新 Redis 缓存
            decrease_memory_size_cache(memory.id, delete_size)
        else:
            # 不支持的策略，写入失败
            error_msg = "Memory size reached limit and cannot decide which to delete."
            if task_id:
                TaskService.update_progress(task_id, {
                    "progress": -1,
                    "progress_msg": timestamp_to_date(current_timestamp()) + " " + error_msg
                })
            return False, error_msg
    
    # 7. 插入新消息
    fail_cases = MessageService.insert_message(message_list, memory.tenant_id, memory.id)
    if fail_cases:
        return False, "Failed to insert message into memory."
    
    # 8. 更新 Redis 缓存（增加新消息大小）
    increase_memory_size_cache(memory.id, new_msg_size)
    return True, "Message saved successfully."
```


**重要限制**：

- 最大值：5MB（5242880 字节）

## 5. 软删除 vs 物理删除对比

| 维度 | 软删除（Forget） | 物理删除（Eviction） |
|------|------------------|---------------------|
| 触发方式 | 用户主动调用 API | 系统自动触发（配额溢出） |
| 实现方式 | 设置 `forget_at` 时间戳 | 从索引删除文档 |
| 检索可见性 | 默认不可见（可通过参数显示） | 永久不可见 |
| 配额占用 | 仍然占用 | 立即释放 |
| 可恢复性 | 可以（清除 `forget_at` 字段） | 不可恢复 |
| 级联操作 | 无 | 可能删除关联的提取记忆 |
| 优先级（淘汰） | FIFO 第一阶段优先清理 | 不适用 |

## 6. Redis 缓存一致性

### 6.1 缓存键格式

```
memory_{memory_id}
```

### 6.2 缓存更新时机

| 操作 | 缓存操作 |
|------|---------|
| 写入新消息 | `INCRBY memory_{id} {new_size}` |
| 物理删除消息 | `DECRBY memory_{id} {deleted_size}` |
| 创建 Memory | 初始化为 0 或全量统计 |
| 删除 Memory | 删除 Redis 键 |
| 缓存未命中 | 全量统计并写入缓存 |

### 6.3 缓存一致性保证

**正常流程**：
- 原子操作（INCRBY/DECRBY）保证并发安全
- 每次写入/删除都同步更新缓存

**异常恢复**：
- Redis 重启后缓存丢失，下次访问时自动全量重建
- 系统启动时可调用 `init_memory_size_cache()` 预热所有 Memory 的缓存

```python
def init_memory_size_cache():
    memory_list = MemoryService.get_all_memory()
    if not memory_list:
        logging.info("No memory found, no need to init memory size.")
    else:
        for m in memory_list:
            get_memory_size_cache(m.id, m.tenant_id)
        logging.info("Memory size cache init done.")
```

**潜在偏差**：
- 全量统计时 `limit=2048 * len(memory_ids)`，超大 Memory 可能统计不完整
- 缓存值可能与实际索引大小存在小幅偏差，不影响功能正确性

## 7. 消息状态管理

除了遗忘机制，Memory 还支持消息级别的启用/禁用：

```python
# api/apps/services/memory_api_service.py
async def update_message_status(memory_id: str, message_id: int, status: bool):
    memory = _require_memory_access(memory_id)
    
    MessageService.update_message(
        {"memory_id": memory_id, "message_id": int(message_id)},
        {"status": status},
        memory.tenant_id,
        memory_id
    )
```

| 字段 | 含义 | 影响 |
|------|------|------|
| `status` | 消息是否启用 | 禁用后不参与检索，但仍占用配额 |
| `forget_at` | 消息是否遗忘 | 遗忘后不参与检索，优先被淘汰 |

三种"不可见"状态的区别：

| 状态 | 检索可见 | 占用配额 | 可恢复 | 淘汰优先级 |
|------|---------|---------|--------|-----------|
| 正常 | 是 | 是 | - | 低（按时间） |
| `status=false` | 否 | 是 | 是 | 低（按时间） |
| `forget_at` 已设置 | 否 | 是 | 是 | 高（第一阶段） |
| 已物理删除 | 否 | 否 | 否 | 已淘汰 |

## 8. Memory 删除时的级联清理

删除整个 Memory 时的清理顺序：

```go
// internal/service/memory.go DeleteMemory
// 1. 删除文档引擎中的索引数据
if err := s.docEngine.DeleteChunkStore(ctx, indexName, memoryID); err != nil {
    slog.Warn("failed to delete memory chunk store", "memory_id", memoryID, "error", err)
}

// 2. 删除 MemoryTask 记录
if err := s.memoryTaskDAO.DeleteByMemoryID(ctx, dao.DB, memoryID); err != nil {
    return errors.New("failed to delete memory tasks")
}

// 3. 删除 Memory 主记录
if err := s.memoryDAO.DeleteByID(ctx, dao.DB, memoryID); err != nil {
    return errors.New("failed to delete memory")
}

// 4. 清理 Redis 缓存
```

删除顺序的设计考量：
- 先删索引数据（幂等，失败仅告警不中断）
- 再删任务记录（避免孤儿任务被 worker 拾取）
- 最后删主记录（作为存在性判定的依据）

## 10. 设计要点总结

1. **两级删除模型**：软删除保留数据供审计与恢复，物理删除释放配额
2. **淘汰前置**：淘汰发生在写入前，保证写入后总大小不超配额
3. **优先淘汰已遗忘**：用户已表达遗忘意图的消息优先被物理清理
4. **Redis 原子计数**：避免每次写入都全量扫描索引，同时保证并发正确性
5. **缓存可重建**：Redis 只是加速层，丢失后可从索引全量恢复
6. **策略可扩展**：`forgetting_policy` 字段预留了 FIFO 之外的策略空间，当前实现仅 FIFO
