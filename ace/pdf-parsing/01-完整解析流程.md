# RAGFlow PDF 多页解析完整流程

## 概述

本文档详细描述 RAGFlow 对多页 PDF 文档的完整解析流程，包括每个阶段的输入输出数据格式。

## 场景设定

假设我们有一个 **3 页的 PDF 产品手册**：
- **第 1 页**：封面 + 产品标题 + 简介文本
- **第 2 页**：产品规格表格 + 说明文本
- **第 3 页**：联系信息 + 页脚

---

## 完整流程概览

```
PDF 文件
  ↓
[阶段 1] OCR 文字识别
  ↓
[阶段 2] 布局分析
  ↓
[阶段 3] 表格结构识别
  ↓
[阶段 4] 文本合并
  ↓
[阶段 5] 提取章节、表格、图片
  ↓
[阶段 6] 分块（naive_merge）
  ↓
[阶段 7] Token 化并生成最终 Chunks
  ↓
存储到 Elasticsearch/Infinity
```

---

## 阶段 7：Token 化并生成最终 Chunks

### 输入
- 阶段 6 的 chunks（文本块列表）
- 文档元数据（`doc`）：包含 `doc_id`, `kb_id`, `docnm_kwd` 等
- PDF 解析器实例（`pdf_parser`，如果是 PDF 文档）
- 语言设置（`language`，默认 "English"）

### 什么是 Token 化（Tokenization）

Token 化是将文本分解为更小的语义单元（tokens）的过程，主要用于两个目的：

1. **全文检索分词**：将文本拆分为词汇单元，用于 BM25 等关键词检索算法
2. **Token 计数**：使用与 LLM（如 GPT-4）相同的编码器计算文本的 token 数量，用于控制上下文长度

在 RAGFlow 中，token 化包含三个层次：

- **`content_with_weight`**：原始文本内容（去除 HTML 表格标签后的纯文本）
- **`content_ltks`**：粗粒度分词结果（用于 BM25 全文检索）
- **`content_sm_ltks`**：精细分词结果（用于短文本精确匹配）

### 处理流程

调用 `rag/nlp/__init__.py` 中的 `tokenize_chunks()` 函数：

1. **遍历每个 chunk**
   - 跳过空白 chunk
   - 复制文档元数据模板

2. **添加位置信息**
   - 如果是 PDF：调用 `pdf_parser.crop()` 提取 chunk 对应的页面区域和位置（bbox）
   - 如果是 TXT：使用索引占位符 `[[ii] * 5]`

3. **执行 token 化**（`tokenize()` 函数）
   ```python
   # 伪代码
   d["content_with_weight"] = txt  # 保存原始文本
   t = re.sub(r"</?(table|td|caption|tr|th)( [^<>]{0,12})?>", " ", txt)  # 移除表格标签
   d["content_ltks"] = rag_tokenizer.tokenize(t)  # 粗粒度分词
   d["content_sm_ltks"] = rag_tokenizer.fine_grained_tokenize(d["content_ltks"])  # 精细分词
   ```

4. **计算 token 数量**（在后续的 embedding 阶段）
   - 使用 `num_tokens_from_string()` 函数（来自 `common/token_utils.py`）
   - 采用 **tiktoken cl100k_base** 编码器（与 OpenAI GPT-3.5/GPT-4 相同）
   - 公式：`token_num = len(encoder.encode(text, disallowed_special=()))`

### Token 数量的计算方式

RAGFlow 使用 **tiktoken cl100k_base 编码器**计算 token 数量，这是 OpenAI GPT-3.5 和 GPT-4 使用的标准编码器。

**核心函数**：`common/token_utils.py` 中的 `num_tokens_from_string()`

```python
def num_tokens_from_string(string: str) -> int:
    """Returns the number of tokens in a text string."""
    enc = tiktoken.get_encoding("cl100k_base")
    try:
        code_list = enc.encode(string, disallowed_special=())
        return len(code_list)
    except Exception:
        return 0
```

**计算示例**：
- 英文："Hello world" → 2 tokens
- 中文："你好世界" → 4 tokens（中文字符通常 1-2 个字符占 1 个 token）
- 混合："智能手表产品手册" → 约 6-8 tokens

**使用场景**：
- 阶段 4（段落合并）：使用 `num_tokens_from_string()` 控制合并后的 chunk 大小（如 128 tokens）
- 阶段 7（最终 chunks）：计算每个 chunk 的 `token_num` 字段，用于检索时的上下文控制

## 检索和高亮流程

### 用户查询："智能手表的续航时间是多少？"

1. **向量检索**：
   - 将查询文本转换为 768 维向量
   - 使用向量相似度搜索（cosine similarity）找到最相关的 chunks
   - 返回 top-k 结果（如 top-5）

2. **关键词检索**（混合检索）：
   - 同时使用 BM25 算法进行关键词匹配
   - 与向量检索结果进行融合（Hybrid Search）

3. **高亮显示**：
   - 获取匹配 chunk 的 `positions` 字段
   - 在前端 PDF 查看器中根据坐标高亮显示相关文本
   - 用户可以看到原文档中的精确位置

## 总结

完整的 PDF 解析流程包括 **7 个主要阶段**：

1. **OCR 文字识别**：提取文本和坐标
2. **布局分析**：识别标题、正文、表格、图片等
3. **表格结构识别**：解析表格的行列结构
4. **文本合并**：将碎片化的文本框合并成段落
5. **提取章节、表格、图片**：按类型分组
6. **分块（naive_merge）**：生成合适大小的检索单元
7. **Token 化和向量化**：生成 embedding 并存储

最终生成的 **Chunk** 对象包含：
- 文本内容和关键词
- 768 维向量 embedding
- 原文档的精确位置信息（支持高亮显示）
- 元数据（文档类型、创建时间等）

这套流程既保证了**检索的准确性**（通过向量 + 关键词混合检索），又保证了**结果的可追溯性**（通过位置信息高亮显示原文）。
