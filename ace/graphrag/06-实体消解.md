### 2.3 相似度判断算法

**函数**: `is_similarity()` ([entity_resolution.py:275-289](file:///d:/work/rag/ragflow/rag/graphrag/entity_resolution.py#L275-L289))

```python
def is_similarity(self, a, b):
    # 过滤1: 2-gram 差异中包含数字 → 不相似
    if self._has_digit_in_2gram_diff(a, b):
        return False
    
    # 英文实体: 使用 Levenshtein 编辑距离
    if is_english(a) and is_english(b):
        if Levenshtein.distance(a, b) <= min(len(a), len(b)) // 2:
            return True
        return False
    
    # 中文/其他语言: 使用字符集合 Jaccard 相似度
    a, b = set(a), set(b)
    max_l = max(len(a), len(b))
    if max_l < 4:
        return len(a & b) > 1
    
    return len(a & b) * 1.0 / max_l >= 0.8
```

**分层策略**:

#### (1) 数字敏感过滤

**函数**: `_has_digit_in_2gram_diff()` ([entity_resolution.py:265-273](file:///d:/work/rag/ragflow/rag/graphrag/entity_resolution.py#L265-L273))

```python
def _has_digit_in_2gram_diff(self, a, b):
    def to_2gram_set(s):
        return {s[i : i + 2] for i in range(len(s) - 1)}
    
    set_a = to_2gram_set(a)
    set_b = to_2gram_set(b)
    diff = set_a ^ set_b  # 对称差集
    
    return any(any(c.isdigit() for c in pair) for pair in diff)
```

**目的**: 防止"Company 2023" 和 "Company 2024" 被误判为相似。

**示例**:
- `"Apple Inc 2023"` vs `"Apple Inc 2024"` → 2-gram 差异包含 `"23"`, `"20"`, `"24"` → 返回 `True` (有数字) → **不相似**
- `"Microsoft"` vs `"MicroSoft"` → 2-gram 差异不包含数字 → 继续下一步判断

#### (2) 英文实体: Levenshtein 距离

```python
if Levenshtein.distance(a, b) <= min(len(a), len(b)) // 2:
    return True
```

**阈值**: 编辑距离 ≤ 较短名称长度的一半。

**示例**:
- `"Beijing"` vs `"Peking"` → 距离 5, 阈值 7//2=3 → **不相似** (需 LLM 判断)
- `"Chicago"` vs `"Chicgo"` → 距离 1, 阈值 7//2=3 → **相似**

#### (3) 中文/其他: 字符集合 Jaccard

```python
a, b = set(a), set(b)
max_l = max(len(a), len(b))
if max_l < 4:
    return len(a & b) > 1
return len(a & b) * 1.0 / max_l >= 0.8
```

**短名称特殊处理**: 字符集合长度 < 4 时，只需交集 > 1 即认为相似。

**示例**:
- `"上海"` vs `"上海市"` → 交集 `{"上", "海"}`, max_l=3, 2/3=0.66 → **不相似**（但 max_l < 4 规则，2 > 1 → 相似）
- `"北京大学"` vs `"清华大学"` → 交集 `{"大", "学"}`, max_l=4, 2/4=0.5 < 0.8 → **不相似**

### 2.6 LLM 响应解析

**函数**: `_process_results()` ([entity_resolution.py:245-263](file:///d:/work/rag/ragflow/rag/graphrag/entity_resolution.py#L245-L263))

```python
def _process_results(self, records_length: int, results: str, record_delimiter: str, entity_index_delimiter: str, resolution_result_delimiter: str) -> list:
    ans_list = []
    records = [r.strip() for r in results.split(record_delimiter)]
    for record in records:
        # 提取问题编号
        pattern_int = rf"{re.escape(entity_index_delimiter)}(\d+){re.escape(entity_index_delimiter)}"
        match_int = re.search(pattern_int, record)
        res_int = int(str(match_int.group(1) if match_int else "0"))
        if res_int > records_length:
            continue
        
        # 提取判断结果 (yes/no)
        pattern_bool = f"{re.escape(resolution_result_delimiter)}([a-zA-Z]+){re.escape(resolution_result_delimiter)}"
        match_bool = re.search(pattern_bool, record)
        res_bool = str(match_bool.group(1) if match_bool else "")
        
        if res_int and res_bool:
            if res_bool.lower() == "yes":
                ans_list.append((res_int, "yes"))
    
    return ans_list
```

**返回示例**: `[(1, "yes"), (5, "yes")]` → 表示第 1 和第 5 对实体需要合并。

### 3.3 节点合并逻辑

**函数**: `_merge_graph_nodes()` (在 `Extractor` 基类或 `EntityResolution` 中实现，推测逻辑类似 `graph_merge`)

**推测实现** (基于 05 文档中的 `graph_merge` 逻辑):

```python
async def _merge_graph_nodes(self, graph: nx.Graph, nodes: list[str], change: GraphChange, task_id: str = ""):
    # 选择一个主节点（通常是第一个或 PageRank 最高的）
    primary_node = nodes[0]
    nodes_to_remove = nodes[1:]
    
    # 合并属性
    for node in nodes_to_remove:
        graph.nodes[primary_node]["description"] += GRAPH_FIELD_SEP + graph.nodes[node]["description"]
        graph.nodes[primary_node]["source_id"] += graph.nodes[node]["source_id"]
    
    # 重定向所有边
    for node in nodes_to_remove:
        for neighbor in list(graph.neighbors(node)):
            if neighbor == primary_node:
                continue
            edge_attr = graph.get_edge_data(node, neighbor)
            existing_edge = graph.get_edge_data(primary_node, neighbor)
            if existing_edge:
                # 合并边属性
                existing_edge["weight"] += edge_attr.get("weight", 0)
                existing_edge["description"] += GRAPH_FIELD_SEP + edge_attr["description"]
                existing_edge["keywords"] += edge_attr["keywords"]
                existing_edge["source_id"] += edge_attr["source_id"]
                change.added_updated_edges.add(get_from_to(primary_node, neighbor))
            else:
                # 创建新边
                graph.add_edge(primary_node, neighbor, **edge_attr)
                change.added_updated_edges.add(get_from_to(primary_node, neighbor))
            change.removed_edges.add(get_from_to(node, neighbor))
        
        # 删除旧节点
        graph.remove_node(node)
        change.removed_nodes.add(node)
    
    change.added_updated_nodes.add(primary_node)
```

**关键操作**:
1. 保留一个主节点，删除其他节点
2. 主节点继承所有被删节点的描述、source_id
3. 所有连接到被删节点的边重定向到主节点
4. 重复边的属性累加合并

## 六、性能优化点

1. **增量消解**: 只对新合并的子图节点进行候选对筛选（`a in subgraph_nodes or b in subgraph_nodes`）
2. **相似度预筛**: 使用快速字符串匹配排除 80%+ 的明显不同实体，减少 LLM 调用
3. **批量判断**: 每次 LLM 调用处理 100 对实体，减少网络往返
4. **并发控制**: 限制并发数为 5，避免触发 LLM API 限流
5. **Checkpoint 恢复**: 崩溃后可从已保存的判断结果继续，避免重复计算
6. **类型隔离**: 只在同类型实体间消解，避免无意义的跨类型比较
7. **数字敏感**: 快速排除包含数字差异的实体对（如年份、版本号）

## 八、Prompt 设计分析

### 8.1 Few-shot 示例

**Prompt 模板**: [entity_resolution_prompt.py:29-67](file:///d:/work/rag/ragflow/rag/graphrag/entity_resolution_prompt.py#L29-L67)

**Example 1: Product**
```
Demonstration 1: name of Product A is : "computer", name of Product B is :"phone"  
No, Product A and Product B are different products.

Question 1: name of Product A is : "television", name of Product B is :"TV"  
→ Output: (For question <|>1<|>, &&no&&, ...)

Question 3: name of Product A is : "soccer", name of Product B is :"football"  
→ Output: (For question <|>3<|>, &&yes&&, Product A and Product B are the same product.)
```

**Example 2: Toponym**
```
Demonstration 1: name of toponym A is : "nanjing", name of toponym B is :"nanjing city"  
Yes, toponym A and toponym B are same toponym.

Question 3: name of toponym A is : "Beijing", name of toponym B is :"Peking"
→ Output: (For question <|>3<|>, &&yes&&, toponym A and toponym B are the same toponym.)
```

**设计目的**:
- 教会 LLM 识别别名（TV = Television, Beijing = Peking）
- 教会 LLM 领域知识（soccer = football 在某些地区）
- 教会 LLM 严格的输出格式（必须包含分隔符）

---

### 8.2 输出格式强制

**关键指令**:
```
Use domain knowledge of {entity_type}s to help understand the text and answer the above {N} questions in the format: For Question i, Yes, {entity_type} A and {entity_type} B are the same {entity_type}. or No, {entity_type} A and {entity_type} B are different {entity_type}s. For Question i+1, (repeat the above procedures)
```

**分隔符嵌入**:
- `{entity_index_delimiter}` → `<|>`
- `{resolution_result_delimiter}` → `&&`
- `{record_delimiter}` → `##`

**鲁棒性**: 正则表达式解析容忍 LLM 输出中的额外文本，只提取关键信息。
