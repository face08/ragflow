# 02 任务调度链路

本文档描述从文档上传到 GraphRAG 任务启动的完整调度链路。

## 1. 整体调用链

```
POST /api/v1/document/upload
  ↓
document_api.py: upload_document()
  ↓
document_service.py: save(..., run=TASK_MODE)
  ↓
task_service.py: queue_tasks(...)
  ↓
Redis task queue (PipelineTaskType.GRAPH_RAG)
  ↓
task_executor.py: do_handle_task()
  ↓
task_executor.py: GRAPH_RAG 分支处理
  ↓
index.py: run_graphrag_for_kb(...)
  ↓
[GraphRAG 主流程执行]
```

## 2. 文档上传 API

入口：[document_api.py](file:///d:/work/rag/ragflow/api/apps/restful_apis/document_api.py)

```python
@manager.route("/upload", methods=["POST"])
@validate_request("kb_id")
def upload_document():
    kb_id = request.form.get("kb_id")
    # 文件上传到 MinIO/S3
    for file in request.files.getlist("file"):
        blob = file.read()
        storage.put(bucket, name, blob)
        
        # 保存文档记录并触发任务
        document_service.save(
            kb_id=kb_id,
            name=name,
            location=name,
            size=len(blob),
            run=TASK_MODE.AUTO,  # 自动启动解析任务
        )
```

关键参数：
- `run=TASK_MODE.AUTO`：立即创建解析任务
- `run=TASK_MODE.HOLD`：仅保存文档，稍后手动触发

## 3. 文档保存与任务入队

### 3.1 document_service.save

[document_service.py](file:///d:/work/rag/ragflow/api/db/services/document_service.py) 负责：

1. 插入 `Document` 记录到数据库
2. 如果 `run != TASK_MODE.HOLD`，调用 `task_service.queue_tasks`

```python
def save(kb_id, name, location, size, run=TASK_MODE.AUTO, **kwargs):
    doc = {
        "id": uuid4().hex,
        "kb_id": kb_id,
        "name": name,
        "location": location,
        "size": size,
        "status": TaskStatus.UNSTART,
        "create_time": datetime.now(),
        **kwargs
    }
    DocumentService.insert(doc)
    
    if run != TASK_MODE.HOLD:
        # 立即入队
        task_service.queue_tasks(doc, bucket, location, priority=1)
    
    return doc
```

### 3.2 task_service.queue_tasks

[task_service.py:444-593](file:///d:/work/rag/ragflow/api/db/services/task_service.py#L444-L593) 的核心逻辑：

```python
def queue_tasks(doc: dict, bucket: str, name: str, priority: int, user_id: str | None = None):
    kb = KnowledgebaseService.get_by_id(doc["kb_id"])
    chunking_config = kb.get("parser_config", )
    
    # 1. 构造任务摘要（digest），用于复用优化
    digest_config = copy.deepcopy(chunking_config)
    # 排除 graphrag 和 raptor 配置，因为它们是后置任务，不影响 chunk 结果
    if "parser_config" in digest_config:
        for k in ["raptor", "graphrag"]:
            if k in digest_config["parser_config"]:
                del digest_config["parser_config"][k]
    
    task_digest = hashlib.md5(
        (doc["parser_id"] + json.dumps(digest_config, sort_keys=True)).encode()
    ).hexdigest()
    
    # 2. 创建主解析任务
    task = {
        "id": uuid4().hex,
        "doc_id": doc["id"],
        "kb_id": doc["kb_id"],
        "tenant_id": kb["tenant_id"],
        "task_type": PipelineTaskType.PARSER,
        "from_page": 0,
        "to_page": -1,  # 全文档
        "progress": 0.0,
        "progress_msg": "",
        "create_time": datetime.now(),
        "update_time": datetime.now(),
        "retry_count": 0,
        "digest": task_digest,
        **chunking_config,
    }
    
    TaskService.insert(task)
    
    # 3. 推送到 Redis 队列
    redis_conn.queue_product(
        PipelineTaskType.PARSER,
        message=json.dumps({"id": task["id"]}),
        priority=priority,
    )
    
    # 4. 如果启用 GraphRAG，创建后置任务
    if chunking_config.get("parser_config", {}).get("graphrag", {}).get("use_graphrag"):
        graphrag_task = {
            "id": uuid4().hex,
            "doc_id": doc["id"],
            "kb_id": doc["kb_id"],
            "tenant_id": kb["tenant_id"],
            "task_type": PipelineTaskType.GRAPH_RAG,
            "create_time": datetime.now(),
            **chunking_config,
        }
        TaskService.insert(graphrag_task)
        # GraphRAG 任务稍后手动触发，或在解析完成后自动触发
```

**关键设计**：
- GraphRAG 任务入库但**不立即入队**，等主解析任务完成后再触发
- 任务摘要（digest）排除了 `graphrag` 配置，因为 GraphRAG 是在 chunk 之上的后处理，不影响 chunk 本身的复用判定

## 4. 任务执行器分发

### 4.1 任务消费循环

[task_executor.py](file:///d:/work/rag/ragflow/rag/svr/task_executor.py) 的主循环：

```python
async def main():
    while True:
        # 从 Redis 拉取任务
        task_msg = redis_conn.queue_consume(
            [PipelineTaskType.PARSER, PipelineTaskType.GRAPH_RAG],
            timeout=1,
        )
        
        if task_msg:
            task_id = json.loads(task_msg)["id"]
            task = TaskService.get_by_id(task_id)
            
            # 分发到处理函数
            asyncio.create_task(do_handle_task(task))
```

### 4.2 GraphRAG 任务分支

[task_executor.py:1586-1634](file:///d:/work/rag/ragflow/rag/svr/task_executor.py#L1586-L1634)：

```python
async def do_handle_task(task: dict):
    task_type = task["task_type"]
    
    if task_type == PipelineTaskType.GRAPH_RAG:
        tenant_id = task["tenant_id"]
        kb_id = task["kb_id"]
        doc_ids = task.get("doc_ids") or []
        language = task.get("language") or "English"
        
        # 获取 GraphRAG 配置
        graphrag_conf = get_kb_doc_parser_config(task)
        graphrag_conf = graphrag_conf.get("graphrag", {})
        
        # 填充默认配置
        if not graphrag_conf.get("entity_types"):
            graphrag_conf["entity_types"] = [
                "organization", "person", "geo", "event", "category"
            ]
        if not graphrag_conf.get("method"):
            graphrag_conf["method"] = "light"
        if not graphrag_conf.get("batch_chunk_token_size"):
            graphrag_conf["batch_chunk_token_size"] = 4096
        
        # 超时配置
        if not graphrag_conf.get("build_subgraph_timeout_per_chunk_seconds"):
            graphrag_conf["build_subgraph_timeout_per_chunk_seconds"] = 300
        if not graphrag_conf.get("build_subgraph_min_timeout_seconds"):
            graphrag_conf["build_subgraph_min_timeout_seconds"] = 600
        if not graphrag_conf.get("merge_timeout_seconds"):
            graphrag_conf["merge_timeout_seconds"] = 180
        if not graphrag_conf.get("resolution_timeout_seconds"):
            graphrag_conf["resolution_timeout_seconds"] = 1800
        if not graphrag_conf.get("community_timeout_seconds"):
            graphrag_conf["community_timeout_seconds"] = 1800
        if not graphrag_conf.get("lock_acquire_timeout_seconds"):
            graphrag_conf["lock_acquire_timeout_seconds"] = 600
        
        # 重试配置
        if not graphrag_conf.get("retry_attempts"):
            graphrag_conf["retry_attempts"] = 2
        if not graphrag_conf.get("retry_backoff_seconds"):
            graphrag_conf["retry_backoff_seconds"] = 2.0
        if not graphrag_conf.get("retry_backoff_max_seconds"):
            graphrag_conf["retry_backoff_max_seconds"] = 60.0
        
        # 可选阶段开关
        with_resolution = graphrag_conf.get("resolution", False)
        with_community = graphrag_conf.get("community", False)
        
        # 获取模型实例
        chat_mdl = LLMBundle(tenant_id, LLMType.CHAT, llm_name=task.get("llm_id"))
        embd_mdl = LLMBundle(tenant_id, LLMType.EMBEDDING, llm_name=task.get("embd_id"))
        
        # 进度回调
        def callback(prog: float, msg: str):
            TaskService.update_progress(task["id"], prog, msg)
        
        # 调用主流程
        await run_graphrag_for_kb(
            task,
            doc_ids,
            language,
            graphrag_conf,
            chat_mdl,
            embd_mdl,
            callback,
            with_resolution=with_resolution,
            with_community=with_community,
            max_parallel_docs=4,
        )
```

## 5. 配置传递链路

```
Knowledgebase.parser_config.graphrag
  ↓ (存储在 KB 表)
task_service.queue_tasks(...)
  ↓ (写入 Task.parser_config)
task_executor.do_handle_task(...)
  ↓ (读取 Task.parser_config.graphrag)
填充默认值
  ↓
run_graphrag_for_kb(graphrag_conf)
```

关键字段：

| 字段 | 默认值 | 含义 |
|---|---|---|
| `use_graphrag` | `True` | 是否启用 GraphRAG |
| `method` | `"light"` | 抽取器类型：general / light / ner |
| `entity_types` | `["organization", "person", ...]` | 需要抽取的实体类型 |
| `batch_chunk_token_size` | `4096` | 每批次 chunk 的 token 上限 |
| `resolution` | `False` | 是否做实体消解 |
| `community` | `False` | 是否做社区检测 |
| `retry_attempts` | `2` | LLM 调用重试次数 |
| `*_timeout_seconds` | 见代码 | 各阶段超时控制 |

## 6. 任务触发时机

GraphRAG 任务有两种触发方式：

### 6.1 自动触发

当主解析任务完成后，`task_executor` 检查是否有待执行的 GraphRAG 任务，自动将其入队：

```python
# 在 PARSER 任务完成后
if task["task_type"] == PipelineTaskType.PARSER:
    # 检查是否有 GRAPH_RAG 后置任务
    graphrag_tasks = TaskService.filter(
        doc_id=task["doc_id"],
        task_type=PipelineTaskType.GRAPH_RAG,
        status=TaskStatus.UNSTART,
    )
    for gt in graphrag_tasks:
        redis_conn.queue_product(
            PipelineTaskType.GRAPH_RAG,
            message=json.dumps({"id": gt["id"]}),
            priority=1,
        )
```

### 6.2 手动触发

用户可以通过 API 手动触发知识库级别的 GraphRAG 任务：

```python
POST /api/v1/kb/{kb_id}/graphrag
{
    "doc_ids": ["doc1", "doc2"],  # 可选，默认全部文档
    "resolution": True,            # 可选，是否消解
    "community": True              # 可选，是否社区检测
}
```

后端创建一个新的 `GRAPH_RAG` 任务，直接入队执行。

## 7. 任务状态流转

```
UNSTART (已创建)
  ↓
RUNNING (执行中，定期更新 progress)
  ↓
SUCCESS (成功) / FAILURE (失败)
```

状态更新通过 `callback(progress, message)` 实时写入数据库，前端轮询 Task 表获取进度。

## 8. 小结

调度链路的关键设计：

1. **分离 chunk 与图谱任务**：解析任务生成 chunk，GraphRAG 任务消费 chunk，二者通过任务队列解耦
2. **延迟入队**：GraphRAG 任务创建时不入队，等 chunk 就绪后再触发，避免空跑
3. **配置继承**：GraphRAG 配置存储在 KB 级别，所有文档共享，任务执行时读取并填充默认值
4. **进度透明**：通过回调函数实时更新任务状态，前端可展示详细进度
