# 01 架构总览

## 1. 模块定位

RAGFlow 的检索能力分两层：

1. **向量/全文检索层**：文档被切成 chunk，做 embedding，写入文档库（Elasticsearch / Infinity / OpenSearch）。
2. **图谱增强层（GraphRAG）**：在已有 chunk 之上，用 LLM 抽取实体与关系，构造知识图谱，再把图谱的节点、边、社区报告也当作特殊 chunk 写回同一索引。

关键设计：**图谱不是独立存储系统**。实体、关系、社区报告都以 chunk 记录形式存在文档库里，通过 `knowledge_graph_kwd` 字段区分类型。这让检索阶段无需引入图数据库，一次查询即可同时命中文本和图谱内容。

## 3. 三种抽取器对比

配置项 `parser_config.graphrag.method`，默认 `light`。

| 维度 | general | light | ner |
|---|---|---|---|
| 来源 | Microsoft GraphRAG | LightRAG | spaCy |
| 依赖 | LLM | LLM | 本地 NER 模型 |
| 提示词风格 | 单次长提示，要求输出完整实体+关系列表 | 结构化分隔符输出，支持迭代 gleaning | 无提示词 |
| gleaning | 支持（continue prompt 复采） | 支持（loop 判定 + continue） | 不适用 |
| 成本 | 高 | 中 | 极低 |
| 关系质量 | 描述较丰富 | 带 keywords/weight 字段 | 仅共现关系，无语义描述 |
| 适用场景 | 需要高质量图谱、成本不敏感 | 通用默认选择 | 大规模、低成本、只需实体索引 |

### general 抽取器要点

提示词要求 LLM 一次性输出所有实体与关系，格式为带分隔符的元组列表：

```
("entity"<|>NAME<|>TYPE<|>DESCRIPTION)##
("relationship"<|>SOURCE<|>TARGET<|>DESCRIPTION<|>STRENGTH)##
<|COMPLETE|>
```

抽取后如果判定可能遗漏，追加 continue prompt 再采一轮（gleaning）。

### light 抽取器要点

[light/graph_extractor.py](file:///d:/work/rag/ragflow/rag/graphrag/light/graph_extractor.py) 的核心循环：

```python
for now_glean_index in range(self._max_gleanings):
    glean_result = await self._chat(self._continue_prompt, hist, gen_conf)
    # 合并本轮结果
    if now_glean_index == self._max_gleanings - 1:
        break
    if_loop_result = await self._chat(self._if_loop_prompt, hist, gen_conf)
    if if_loop_result.strip().lower() != "yes":
        break
```

先用 `_if_loop_prompt` 问 LLM「还有遗漏吗」，回答 yes 才继续，避免无意义的额外调用。

### ner 抽取器要点

用 spaCy 做命名实体识别，同一 chunk 内共现的实体之间建立边。不产生语义描述，速度快但图谱语义弱。

## 4. 核心数据结构

### 4.1 图对象

内存中使用 `networkx.Graph`（无向图）：

```python
graph = nx.Graph()

# 节点属性
graph.nodes[name] = {
    "entity_name": str,          # 实体名（大写归一化）
    "entity_type": str,          # 实体类型
    "description": str,          # 多来源描述拼接/摘要
    "source_id": str,            # 来源 chunk id，<SEP> 分隔
    "pagerank": float,           # 全局图上计算
    "rank": int,                 # 度数
}

# 边属性
graph.edges[src, tgt] = {
    "weight": float,             # 关系强度累加
    "description": str,          # 关系描述
    "keywords": list[str],       # 关键词（light 方法产出）
    "source_id": str,            # 来源 chunk id
}
```

### 4.2 GraphChange

增量变更集，避免每次全量重写文档库：

```python
@dataclass
class GraphChange:
    removed_nodes: set[str]
    added_updated_nodes: set[str]
    removed_edges: set[tuple[str, str]]
    added_updated_edges: set[tuple[str, str]]
```

### 4.3 文档库中的图谱表示

图谱通过 `knowledge_graph_kwd` 字段区分记录类型：

| `knowledge_graph_kwd` | 含义 | 关键字段 |
|---|---|---|
| `graph` | 全局图的元信息与边列表 | `content_with_weight`（图 JSON） |
| `subgraph` | 单文档子图，用于增量重建 | `doc_id`, `content_with_weight` |
| `entity` | 实体节点 | `entity_kwd`, `entity_type_kwd`, `rank_int`, `pagerank_flt` |
| `relation` | 关系边 | `from_entity_kwd`, `to_entity_kwd`, `weight_int` |
| `community_report` | 社区报告 | `entities_kwd`, `content_with_weight` |

实体和关系记录都带 `q_%d_vec` 向量字段，因此可以被向量检索直接命中。

另外两个开关不在默认配置里，需要显式打开：

- `resolution`: 是否做实体消解，默认 `False`
- `community`: 是否做社区检测与报告，默认 `False`

对应 [task_executor.py:1590-1591](file:///d:/work/rag/ragflow/rag/svr/task_executor.py#L1590-L1591)：

```python
with_resolution = graphrag_conf.get("resolution", False)
with_community = graphrag_conf.get("community", False)
```

这意味着开箱默认只做「实体关系抽取 + 子图合并」，消解和社区是可选增强，因为二者都很贵。
