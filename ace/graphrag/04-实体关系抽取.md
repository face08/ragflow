# 04 - 实体关系抽取

## 概述

实体关系抽取是 GraphRAG 知识图谱构建的核心环节，负责从文本批次中识别出实体（Entity）和实体间的关系（Relationship）。RAGFlow 提供了三种抽取方法：

| 方法 | 实现类 | 技术路线 | LLM 依赖 |
|---|---|---|---|
| **general** | `rag.graphrag.general.extractor.Extractor` | Microsoft GraphRAG 提示词 + Gleaning | 强依赖 |
| **light** | `rag.graphrag.light.graph_extractor.GraphExtractor` | LightRAG 提示词 + Gleaning | 强依赖 |
| **ner** | `rag.graphrag.ner.graph_extractor.NERGraphExtractor` | spaCy NER + 依存句法分析 | 仅描述合并时使用 |

---

## 1. 调用入口

在 `rag/graphrag/general/index.py` 的 `run_graphrag_for_kb` 中，分文档执行抽取：

```python
async def run_graphrag_for_kb(...):
    # ...批次加载完成后
    
    # 根据配置选择抽取器类型
    extractor_type = _select_extractor_type(graphrag_config)
    
    # 为每个文档创建子图生成任务
    async def generate_subgraph_for_doc(doc_id):
        # 1. 加载文档的所有分块批次
        chunks = load_doc_chunks(doc_id)
        
        # 2. 创建对应的抽取器实例
        if extractor_type == "ner":
            extractor = NERGraphExtractor(llm_invoker=chat_model, ...)
        elif extractor_type == "light":
            extractor = GraphExtractor(llm_invoker=chat_model, ...)
        else:  # "general"
            extractor = Extractor(llm_invoker=chat_model, ...)
        
        # 3. 调用抽取器，返回实体和关系列表
        entities, relationships = await extractor(doc_id, chunks, callback, task_id)
        
        # 4. 从实体和关系构建 NetworkX 子图
        subgraph = build_graph_from_entities_and_relations(entities, relationships)
        
        return subgraph
    
    # 并发执行所有文档的抽取
    subgraphs = await asyncio.gather(
        *[generate_subgraph_for_doc(doc_id) for doc_id in doc_ids]
    )
```

抽取器的核心接口是异步调用：

```python
entities, relationships = await extractor(doc_id, chunks, callback, task_id)
```

**返回值**：
- `entities`: `list[dict]`，每个元素包含 `entity_name`, `entity_type`, `description`, `source_id`
- `relationships`: `list[dict]`，每个元素包含 `src_id`, `tgt_id`, `description`, `keywords`, `weight`, `source_id`

## 2. General / Light 方法：LLM 驱动的抽取

### 2.1 提示词（Prompt）设计

两种方法都基于结构化提示词，要求 LLM 按固定格式输出实体和关系：

**Microsoft GraphRAG 提示词** (`rag/graphrag/general/graph_prompt.py`)：

```
-Goal-
Given a text document, identify all entities and relationships among them.

-Steps-
1. Identify all entities:
   - entity_name: Name (capitalized)
   - entity_type: One of [organization, person, geo, event, category]
   - entity_description: Comprehensive description
   Format: ("entity"<|><entity_name><|><entity_type><|><entity_description>)

2. Identify relationships:
   - source_entity, target_entity
   - relationship_description
   - relationship_strength (numeric score)
   Format: ("relationship"<|><source><|><target><|><description><|><strength>)

3. Return output as a single list, use ## as delimiter.
4. When finished, output <|COMPLETE|>

######################
-Examples-
...
```

**LightRAG 提示词** (`rag/graphrag/light/graph_prompt.py`)：

```
---Goal---
Identify all entities and relationships, use {language} as output.

---Steps---
1. Entity format: ("entity"<|><name><|><type><|><description>)
2. Relationship format: ("relationship"<|><src><|><tgt><|><description><|><keywords><|><strength>)
3. High-level keywords: ("content_keywords"<|><keywords>)
4. Use ## as delimiter.
5. Output <|COMPLETE|>

---Examples---
...

---Real Data---
Entity_types: [organization, person, geo, event, category]
Text:
{input_text}
```

**关键差异**：
- LightRAG 增加了 `relationship_keywords` 和 `content_keywords` 字段
- LightRAG 支持多语言输出（`{language}` 变量）
- 两者都使用相同的分隔符：`<|>` (tuple_delimiter), `##` (record_delimiter), `<|COMPLETE|>` (completion_delimiter)

### 2.2 Gleaning 机制（复采）

Gleaning 是一种迭代重新抽取技术，用于提取 LLM 首次遗漏的实体和关系：

```python
async def _process_single_content(self, chunk_key_dp, chunk_seq, num_chunks, out_results, task_id):
    # 第一轮：完整提示词
    hint_prompt = self._entity_extract_prompt.format(**context_base, input_text=content)
    final_result = await self._async_chat("", [{"role": "user", "content": hint_prompt}], gen_conf, task_id)
    
    # 构建历史对话
    history = pack_user_ass_to_openai_messages(hint_prompt, final_result, self._continue_prompt)
    
    # Gleaning 循环：最多 ENTITY_EXTRACTION_MAX_GLEANINGS (默认2) 次
    for glean_index in range(self._max_gleanings):
        # 提示 LLM 继续抽取
        glean_result = await self._async_chat("", history, gen_conf, task_id)
        final_result += glean_result
        history.extend([{"role": "assistant", "content": glean_result}])
        
        if glean_index == self._max_gleanings - 1:
            break
        
        # 询问 LLM 是否还有遗漏
        history.extend([{"role": "user", "content": self._if_loop_prompt}])
        if_loop_result = await self._async_chat("", history, gen_conf, task_id)
        
        if if_loop_result.strip().lower() != "yes":
            break  # LLM 认为已抽取完整
        
        # 继续下一轮
        history.extend([{"role": "assistant", "content": if_loop_result}, 
                        {"role": "user", "content": self._continue_prompt}])
    
    logging.info(f"Completed {chunk_key} after {glean_index} gleanings")
```

**流程**：
1. **初次抽取**：发送完整的实体抽取提示词
2. **继续提示**：`"MANY entities and relationships were missed. Add them below using same format."`
3. **判断循环**：`"It is possible that there are still entities and relationships missed. Answer YES | NO."`
4. **迭代终止**：达到最大轮次 (`max_gleanings=2`) 或 LLM 回答 `NO`

**优点**：
- 提高召回率，减少首次抽取的遗漏
- 允许 LLM 在上下文中逐步完善结果

**成本**：
- Token 消耗增加 2-3 倍（每轮 Gleaning 都需要重新发送历史）

### 2.3 并发控制

抽取器使用 Semaphore 限制并发：

```python
MAX_CONCURRENT_PROCESS_AND_EXTRACT_CHUNK = int(os.environ.get("MAX_CONCURRENT_PROCESS_AND_EXTRACT_CHUNK", 10))

async def extract_all(doc_id, chunks, max_concurrency=MAX_CONCURRENT_PROCESS_AND_EXTRACT_CHUNK, task_id=""):
    limiter = asyncio.Semaphore(max_concurrency)
    
    async def worker(chunk_key_dp, idx, total, task_id):
        async with limiter:
            await self._process_single_content(chunk_key_dp, idx, total, out_results, task_id)
    
    tasks = [asyncio.create_task(worker((doc_id, ck), i, len(chunks), task_id)) 
             for i, ck in enumerate(chunks)]
    
    await asyncio.gather(*tasks, return_exceptions=False)
```

**并发参数**：
- 默认 10 个 chunk 并发处理
- 每个 chunk 内部串行执行 Gleaning 轮次
- 全局 `chat_limiter` (默认 10) 限制总 LLM 调用并发

### 2.4 响应解析

LLM 返回的文本需要解析成结构化数据：

```python
def _entities_and_relations(self, chunk_key, records, tuple_delimiter):
    maybe_nodes = defaultdict(list)
    maybe_edges = defaultdict(list)
    
    for record in records:
        # 按 tuple_delimiter (<|>) 分割
        record_attributes = split_string_by_multi_markers(record, [tuple_delimiter])
        
        # 尝试解析为实体
        if_entities = handle_single_entity_extraction(record_attributes, chunk_key)
        if if_entities and if_entities["entity_type"].lower() in entity_types:
            maybe_nodes[if_entities["entity_name"]].append(if_entities)
            continue
        
        # 尝试解析为关系
        if_relation = handle_single_relationship_extraction(record_attributes, chunk_key)
        if if_relation:
            maybe_edges[(if_relation["src_id"], if_relation["tgt_id"])].append(if_relation)
    
    return dict(maybe_nodes), dict(maybe_edges)
```

**`handle_single_entity_extraction`** (in `rag/graphrag/utils.py`)：
```python
def handle_single_entity_extraction(record_attributes, chunk_key):
    if len(record_attributes) < 4 or record_attributes[0].strip('"') != "entity":
        return None
    
    return {
        "entity_name": record_attributes[1].strip(),
        "entity_type": record_attributes[2].strip(),
        "description": record_attributes[3].strip(),
        "source_id": [chunk_key],
    }
```

**`handle_single_relationship_extraction`**：
```python
def handle_single_relationship_extraction(record_attributes, chunk_key):
    if len(record_attributes) < 5 or record_attributes[0].strip('"') != "relationship":
        return None
    
    return {
        "src_id": record_attributes[1].strip(),
        "tgt_id": record_attributes[2].strip(),
        "description": record_attributes[3].strip(),
        "keywords": [kw.strip() for kw in record_attributes[4].split(",")],
        "weight": float(record_attributes[5]) if len(record_attributes) > 5 else 1.0,
        "source_id": [chunk_key],
    }
```

**容错处理**：
- 如果 LLM 输出格式不符（字段数不匹配），直接跳过该 record
- 累积错误超过 `GRAPHRAG_MAX_ERRORS` (默认3) 时抛出异常

## 3. NER 方法：spaCy 驱动的无 LLM 抽取

### 3.1 技术路线

NER 方法使用 spaCy 进行命名实体识别和依存句法分析，无需 LLM 参与抽取步骤（仅在后续描述合并时使用）：

```python
class NERGraphExtractor(Extractor):
    def __init__(self, llm_invoker, language=None, entity_types=None):
        super().__init__(llm_invoker, language, entity_types)
        self._nlp = _load_spacy_model("en_core_web_sm")  # 加载 spaCy 模型
```

**实体抽取**：
- spaCy NER 标签 (`PERSON`, `ORG`, `GPE`, `LOC`, `EVENT` 等) 映射到应用层类型
- MGranRAG 多轮合并算法：连字符合并 → 首字母大写合并 → 连续名词/数字合并

**关系推断**：
- LinearRAG 语义桥接：同一句子内共现的实体自动建立关系
- 关系描述 = 共现的句子文本
- 关系权重 = TF 归一化（可选）

### 3.2 优缺点

**优点**：
- 无 LLM 调用成本，速度快（比 LLM 方法快 10-100 倍）
- 适合大规模文档批处理

**缺点**：
- 召回率和准确率低于 LLM 方法
- 关系语义弱（仅基于共现，无明确的语义类型）
- 依赖 spaCy 模型质量（中文需要 `zh_core_web_sm`）

## 4. 节点和边的合并

单个 chunk 内可能重复提到同一实体或关系，需要合并：

### 4.1 节点合并 (`_merge_nodes`)

```python
async def _merge_nodes(self, entity_name, entities, all_entities_data, task_id):
    # 1. 实体类型：出现次数最多的类型
    entity_type = Counter([e["entity_type"] for e in entities]).most_common(1)[0][0]
    
    # 2. 描述：拼接所有不重复描述，用 <SEP> 分隔
    description = GRAPH_FIELD_SEP.join(sorted(set([e["description"] for e in entities])))
    
    # 3. 来源：合并所有 source_id
    source_ids = flat_uniq_list(entities, "source_id")
    
    # 4. 如果描述片段超过12个，触发 LLM 摘要
    description = await self._handle_entity_relation_summary(entity_name, description, task_id)
    
    node_data = {
        "entity_name": entity_name,
        "entity_type": entity_type,
        "description": description,
        "source_id": source_ids,
    }
    all_entities_data.append(node_data)
```

### 4.2 边合并 (`_merge_edges`)

```python
async def _merge_edges(self, src_id, tgt_id, edges_data, all_relationships_data, task_id):
    # 1. 权重：累加所有边的权重
    weight = sum([edge["weight"] for edge in edges_data])
    
    # 2. 描述：拼接所有不重复描述
    description = GRAPH_FIELD_SEP.join(sorted(set([edge["description"] for edge in edges_data])))
    
    # 3. 如果描述片段超过12个，触发 LLM 摘要
    description = await self._handle_entity_relation_summary(f"{src_id} -> {tgt_id}", description, task_id)
    
    # 4. 关键词和来源：去重合并
    keywords = flat_uniq_list(edges_data, "keywords")
    source_id = flat_uniq_list(edges_data, "source_id")
    
    edge_data = {
        "src_id": src_id,
        "tgt_id": tgt_id,
        "description": description,
        "keywords": keywords,
        "weight": weight,
        "source_id": source_id,
    }
    all_relationships_data.append(edge_data)
```

### 4.3 LLM 摘要触发条件

```python
async def _handle_entity_relation_summary(self, entity_or_relation_name, description, task_id):
    # 截断到最大 512 tokens
    use_description = truncate(description, 512)
    description_list = use_description.split(GRAPH_FIELD_SEP)
    
    # 片段数 ≤ 12：直接返回
    if len(description_list) <= 12:
        return use_description
    
    # 片段数 > 12：调用 LLM 摘要
    prompt = SUMMARIZE_DESCRIPTIONS_PROMPT.format(
        entity_name=entity_or_relation_name,
        description_list=description_list,
        language=self._language
    )
    
    async with chat_limiter:
        summary = await self._async_chat("", [{"role": "user", "content": prompt}], {}, task_id)
    
    return summary
```

**SUMMARIZE_DESCRIPTIONS_PROMPT** (in `rag/graphrag/general/graph_prompt.py`)：
```
You are a helpful assistant responsible for generating a comprehensive summary of provided data.
Given entity/relationship descriptions, synthesize them into a single, comprehensive summary.

Entity/Relationship: {entity_name}
Descriptions:
{description_list}

Output:
```

## 5. 缓存与性能优化

### 5.1 LLM 响应缓存

```python
async def _async_chat(self, system, history, gen_conf, task_id):
    # 1. 查询缓存
    response = await thread_pool_exec(get_llm_cache, self._llm.llm_name, system, history, gen_conf)
    if response and not self._is_truncated_cache(response):
        return response
    
    # 2. 调用 LLM
    response = await self._llm.async_chat(system_msg, history, gen_conf)
    
    # 3. 写入缓存（24小时过期）
    await thread_pool_exec(set_llm_cache, self._llm.llm_name, system, response, history, gen_conf)
    
    return response
```

**缓存键**：`xxhash(llm_name + system + history + gen_conf)`

**命中率优化**：
- Gleaning 历史变化导致缓存几乎不命中
- 建议：第一轮提示词缓存，后续轮次不缓存

### 5.2 并发 Token 统计

```python
sum_token_count = 0
for m_nodes, m_edges, token_count in out_results:
    # 每个 worker 返回自己的 token 消耗
    sum_token_count += token_count

logging.info(f"Extraction done, {sum_token_count} tokens used")
```

## 6. 错误处理与任务取消

### 6.1 任务取消检查点

```python
if task_id and has_canceled(task_id):
    raise TaskCanceledException(f"Task {task_id} was cancelled")
```

**检查点位置**：
- 每个 chunk 抽取前
- 每轮 Gleaning 前
- 节点合并前/后
- 边合并前/后

### 6.2 错误累积机制

```python
error_count = 0
max_errors = int(os.environ.get("GRAPHRAG_MAX_ERRORS", 3))

async def worker(chunk_key_dp, idx, total, task_id):
    nonlocal error_count
    try:
        await self._process_single_content(...)
    except Exception as e:
        error_count += 1
        if error_count > max_errors:
            raise Exception(f"Maximum error count ({max_errors}) reached")
```

**容错策略**：
- 单个 chunk 失败不影响其他 chunk
- 累积错误超过阈值时整体失败
- 错误信息通过 `callback(msg=error_msg)` 通知用户

## 小结

实体关系抽取阶段的核心要点：

1. **三种方法**：LLM 驱动（general/light）适合高精度场景，NER 驱动适合大规模低成本场景
2. **Gleaning 机制**：迭代重抽提高召回率，但 Token 成本增加 2-3 倍
3. **并发控制**：Semaphore 限制并发数，防止 LLM API 过载
4. **描述合并**：同名实体/关系的描述拼接后，超过12个片段时触发 LLM 摘要
5. **缓存优化**：LLM 响应缓存减少重复调用，但 Gleaning 历史变化导致命中率低
6. **容错机制**：单 chunk 失败不影响全局，累积错误超阈值时终止任务
