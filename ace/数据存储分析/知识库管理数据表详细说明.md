## 表格概览

| 表名 | 用途 | 主要关联 |
|------|------|----------|
| knowledgebase | 存储知识库的基本信息和配置 | tenant, user |
| document | 存储文档的解析状态和元数据 | knowledgebase, file |
| file | 存储文件/文件夹的树形结构 | knowledgebase, user, file_commit |
| file2document | 文件与文档的多对多关联 | file, document |
| file_commit | 文件的版本提交记录 | file |
| file_commit_item | 单次提交中的具体文件变更项 | file_commit |
| connector | 外部数据源连接器配置 | tenant |
| connector2kb | 连接器与知识库的关联 | connector, knowledgebase |
| sync_logs | 连接器同步日志 | connector, knowledgebase |

## 核心表详解

### 1. knowledgebase - 知识库表

**表名**: `knowledgebase`  
**说明**: 存储知识库的基本信息、解析配置、Embedding 模型、任务进度等核心数据。

#### 字段说明

| 字段名 | 类型 | 索引 | 说明 |
|--------|------|------|------|
| id | CharField(32) | 主键 | 知识库唯一标识 |
| name | CharField(128) | 索引 | 知识库名称 |
| tenant_id | CharField(32) | 索引 | 租户ID,关联 tenant 表 |
| created_by | CharField(32) | 索引 | 创建者用户ID |
| language | CharField(12) | - | 语言设置 |
| embd_id | CharField(32) | - | Embedding 模型ID |
| description | TextField | - | 知识库描述 (GaussDB兼容空字符串) |
| permission | CharField(16) | - | 权限设置 |
| doc_num | IntegerField | - | 文档数量统计 |
| token_num | IntegerField | - | Token 总数统计 |
| chunk_num | IntegerField | - | 分块数量统计 |
| parser_id | CharField(32) | - | 解析器ID |
| parser_config | JSONField | - | 解析器配置(JSON格式) |
| avatar | CharField(1024) | - | 知识库头像URL |

#### 任务追踪字段组 (共12组)

每组包含 3 个字段:`{task_type}_progress`, `{task_type}_num`, `{task_type}_task_ids`,分别记录任务进度、数量和任务ID列表。

支持的任务类型:
- `graphrag`: 图谱RAG任务
- `raptor`: RAPTOR任务
- `mindmap`: 思维导图生成
- `wiki`: Wiki文档处理
- `faq`: FAQ生成
- `tag`: 标签提取
- `entity`: 实体识别
- `summary`: 摘要生成
- `kg`: 知识图谱构建
- `tableqa`: 表格问答
- `translation`: 翻译任务
- `keyword`: 关键词提取

#### 时间字段
- `create_time`: 创建时间 (DateTimeTzField)
- `update_time`: 更新时间 (DateTimeTzField)
- `create_date`: 创建日期 (DateField)
- `update_date`: 更新日期 (DateField)

#### 索引
- 复合索引: `(tenant_id, name)` - 用于租户下的知识库名称查询

### 4. file2document - 文件文档关联表

**表名**: `file2document`  
**说明**: 多对多关联表,一个文件可以产生多个文档(如PDF的不同解析方式),一个文档也可以来自多个文件(如合并文档)。

#### 字段说明

| 字段名 | 类型 | 索引 | 说明 |
|--------|------|------|------|
| id | AutoField | 主键 | 自增ID |
| file_id | CharField(32) | 索引 | 文件ID |
| document_id | CharField(32) | 索引 | 文档ID |

#### 索引
- 复合索引: `(file_id, document_id)` - 保证关联唯一性

**关系说明**:
1. **tenant → knowledgebase**: 一对多,一个租户拥有多个知识库
2. **tenant → connector**: 一对多,一个租户拥有多个连接器
3. **knowledgebase ↔ connector**: 多对多,通过 `connector2kb` 关联
4. **knowledgebase → file**: 一对多,一个知识库包含多个文件
5. **knowledgebase → document**: 一对多,一个知识库包含多个文档
6. **file ↔ document**: 多对多,通过 `file2document` 关联
7. **file → file_commit**: 一对多,一个文件有多个版本提交
8. **file_commit → file_commit_item**: 一对多,一次提交包含多个变更项
9. **connector + kb → sync_logs**: 每次同步产生一条日志

## 数据流转说明

### 1. 文档上传流程

```
用户上传文件
    ↓
创建 file 记录 (type=file, parent_id=folder_id)
    ↓
创建 file_commit 和 file_commit_item (operation=added)
    ↓
创建 document 记录 (status=待解析)
    ↓
创建 file2document 关联
    ↓
异步解析任务处理 document (status=解析中 → 完成)
    ↓
更新 knowledgebase 的 doc_num, token_num, chunk_num
```

### 2. 连接器同步流程

```
定时任务触发 OR 手动触发同步
    ↓
创建 sync_logs 记录 (status=running)
    ↓
连接器拉取外部数据源变更
    ↓
对比本地 file 表,识别新增/修改/删除
    ↓
批量创建 file_commit 和 file_commit_item
    ↓
对新增/修改的文件创建 document 和 file2document
    ↓
更新 sync_logs (status=success, files_added/modified/deleted统计)
    ↓
触发文档解析任务
```

### 3. 版本回滚流程

```
用户选择历史 commit_id
    ↓
查询 file_commit_item 获取该版本的所有文件状态
    ↓
恢复 file 表到该版本状态
    ↓
删除该版本之后的 document 记录
    ↓
重新创建 document 和解析任务
```

## 常用查询示例

### 1. 查询知识库的所有文档及解析状态

```python
from api.db.db_models import Knowledgebase, Document

kb = Knowledgebase.get_by_id("kb_123")
documents = (Document
             .select()
             .where(Document.kb_id == kb.id)
             .order_by(Document.create_time.desc()))

for doc in documents:
    print(f"{doc.name}: {doc.status} - {doc.progress*100:.1f}%")
```

### 2. 查询文件的版本历史

```python
from api.db.db_models import File, FileCommit, FileCommitItem

file = File.get_by_id("file_456")
commits = (FileCommit
           .select()
           .where(FileCommit.file_id == file.id)
           .order_by(FileCommit.commit_time.desc()))

for commit in commits:
    items = FileCommitItem.select().where(FileCommitItem.commit_id == commit.id)
    print(f"Commit {commit.id}: {commit.message}")
    for item in items:
        print(f"  - {item.operation}: {item.name}")
```

### 3. 查询连接器的最近同步记录

```python
from api.db.db_models import Connector, SyncLogs

connector = Connector.get_by_id("conn_789")
recent_syncs = (SyncLogs
                .select()
                .where(SyncLogs.connector_id == connector.id)
                .order_by(SyncLogs.start_time.desc())
                .limit(10))

for log in recent_syncs:
    print(f"{log.start_time}: {log.status}")
    if log.status == "success":
        print(f"  Added: {log.files_added}, Modified: {log.files_modified}, "
              f"Deleted: {log.files_deleted}")
    elif log.status == "failed":
        print(f"  Error: {log.error_message}")
```

### 4. 查询知识库的文件树结构

```python
from api.db.db_models import File

def build_file_tree(kb_id, parent_id=None, indent=0):
    files = File.select().where(
        (File.kb_id == kb_id) &
        (File.parent_id == parent_id)
    ).order_by(File.type.desc(), File.name)
    
    for file in files:
        print("  " * indent + f"{'📁' if file.type == 'folder' else '📄'} {file.name}")
        if file.type == "folder":
            build_file_tree(kb_id, file.id, indent + 1)

build_file_tree("kb_123")
```

### 5. 统计知识库的文档解析情况

```python
from api.db.db_models import Document
from peewee import fn

stats = (Document
         .select(Document.status, fn.COUNT(Document.id).alias('count'))
         .where(Document.kb_id == "kb_123")
         .group_by(Document.status))

for stat in stats:
    print(f"{stat.status}: {stat.count}")
```

## 技术说明

### GaussDB 兼容性

部分字段使用了 `EmptyStringCharField` 和 `EmptyStringTextField` 类型,这是为了兼容 GaussDB 数据库对 NULL 和空字符串的语义差异:

- **标准 SQL**: `NULL` 表示未知/缺失,空字符串 `''` 表示已知的空值
- **GaussDB**: 将空字符串存储为 `NULL`,可能导致业务逻辑错误

这些自定义字段类型在存储时将空字符串转换为 `NULL`,在读取时将 `NULL` 转换回空字符串,保证业务逻辑一致性。

### 索引优化建议

1. **knowledgebase**: `(tenant_id, name)` 复合索引已覆盖常见查询
2. **document**: 考虑添加 `(kb_id, create_time)` 索引用于时间范围查询
3. **file**: `(kb_id, parent_id)` 已优化文件树查询,必要时可添加 `name` 前缀索引
4. **sync_logs**: `start_time` 索引已支持时间序列查询,考虑添加部分索引过滤失败记录

### 维护建议

1. **定期清理**: `sync_logs` 表会快速增长,建议定期归档或删除旧记录
2. **监控**: 关注 `document.progress` 长期停滞的记录,可能是解析任务异常
3. **备份**: `file_commit` 和 `file_commit_item` 是版本管理的关键,务必定期备份
4. **性能**: 对于大型知识库,`chunk_num` 和 `token_num` 统计字段建议异步更新,避免阻塞主流程
